# 電文タイプ別 表示リファレンス

各電文タイプを受電した際のターミナル表示フォーマットの一覧です。
表示処理は以下の4ファイルに分割されています:

- `src/ui/formatter.ts` — 共通表示（フレーム描画・RenderBuffer・recap・表示モード制御）
- `src/ui/eew-formatter.ts` — 緊急地震速報（EEW）の表示
- `src/ui/telegram-type-label.ts` — 電文タイプ名 (`typeLabel`) の共有のみ
- `src/ui/earthquake-info-formatter.ts` — 地震情報 (VXSE51/52/53/61) の表示
- `src/ui/seismic-text-formatter.ts` — 地震活動テキスト情報の表示
- `src/ui/nankai-trough-formatter.ts` — 南海トラフ関連情報の表示
- `src/ui/lg-observation-formatter.ts` — 長周期地震動観測情報の表示（地域テーブル engine 化。1行1地域・hidden 列なしのため `[詳細]` 自体が無い — 2026-07 hidden-only 化）
- `src/ui/tsunami-formatter.ts` — 津波情報の表示（レスポンシブ 3 段 breakpoint・列優先度モデル対応）
- `src/ui/volcano-formatter.ts` — 火山情報の表示

> **常設情報ディスプレイ (display/) のデザインは別文書**: トークン一覧・コントラスト監査・設計意図は
> [`docs/specs/display-design-system.md`](specs/display-design-system.md) を正本とする（本リファレンスは CLI 側 `src/ui/` の表示フォーマット）。

## フレームシステム

すべての電文は「フレーム」で囲まれて表示されます。フレームのスタイルは情報の重大度（`FrameLevel`）に応じて切り替わります。

### フレームレベル一覧

| レベル | 罫線文字 | 色 (CUD) | RGB | HEX | 用途 |
|--------|----------|----------|-----|-----|------|
| `critical` | `╔ ╗ ╚ ╝ ═ ║ ╠ ╣` (二重線) | 朱赤 (バーミリオン) | `rgb(213, 94, 0)` | `#D55E00` | 震度6弱以上、EEW警報、大津波警報、南海トラフ巨大地震警戒 |
| `warning` | `╔ ╗ ╚ ╝ ═ ║ ╠ ╣` (二重線) | オレンジ | `rgb(230, 159, 0)` | `#E69F00` | 震度4以上、EEW予報、津波警報、南海トラフ注意/調査中 |
| `normal` | `┌ ┐ └ ┘ ─ │ ├ ┤` (単線) | スカイブルー | `rgb(86, 180, 233)` | `#56B4E9` | 震度3以下の地震情報、長周期階級2 |
| `info` | `┌ ┐ └ ┘ ─ │ ├ ┤` (単線) | グレー | `rgb(132, 145, 158)` | `#84919E` | テキスト情報、調査終了、長周期階級1以下 |
| `cancel` | `┌ ┐ └ ┘ ─ │ ├ ┤` (単線) | ラズベリー | `rgb(204, 121, 167)` | `#CC79A7` | 取消報 |

### フレーム構造

```
╔══════════════════════════════════════════════════════════╗   ← frameTop
║ (コンテンツ行)                                          ║   ← frameLine
╠══════════════════════════════════════════════════════════╣   ← frameDivider
║ (コンテンツ行)                                          ║   ← frameLine
╚══════════════════════════════════════════════════════════╝   ← frameBottom
```

デフォルト幅: 60 文字（`config.tableWidth` で変更可能）

### テキストの自動折り返し (wrapTextLines v2, spec §9 R3-1/R3-2)

フレーム本文やヘッドライン等の長文は、表示幅に合わせて `wrapTextLines` で自動折り返しされる。アルゴリズムは以下の 3 本柱:

- **幅充填**: 各行を幅いっぱいまで詰める (半端な早折りをしない)。
- **句読点優先改行**: 折返し点の手前 `BREAK_LOOKBACK = 12` 文字以内に句読点 (`、。，．,.`) があれば、その直後で折る。**句読点は前行末に残す** (v1 の「、」区切り分割で行末読点が脱落していたバグは、delimiter から「、」を除去し本経路に一本化したことで解消。読点を含む長文も本文文字列は lossless)。
- **禁則処理**: 行頭禁則 (`、。）」…・！？` 等) / 行末禁則 (開き括弧 `（「` 等) を最大 4 文字の追い込み・追い出しで調整。調整幅を超える場合は fail-open (調整なしで改行) する。検査文字集合は `KINSOKU_LINE_START` / `KINSOKU_LINE_END` として export され、snapshot 全体の禁則違反を検出する恒久テスト (`test/ui/kinsoku-snapshot.test.ts`) が実装定数を直接 import する。

wrap 列を持つテーブル (地震 震度分布・降灰 地域列・火山バッチ 注目地域など) では、`wrapTextLines` が lossless (offset 追跡のためスペースを保持) で返した継続行の先頭スペース 1 個 (カンマ折り直後の残り) を engine 側で除去する。これによりカンマ区切りの地域リストは前行末にカンマが残り、継続行がカンマや余分な空白で始まらない。

VFVO53 ヘッドライン (幅 60) の例。句点直後で折り (`です。` で改行)、行頭に読点が来ないよう `場合に` / `は、以下…` と追い出し調整されている:

```
├──────────────────────────────────────────────────────────┤
│  現在、桜島は噴火警戒レベル３（入山規制）です。          │
│  桜島で噴火が発生した場合には、１７日２１時から２４時ま  │
│  では火口から北東方向に降灰が予想されます。              │
├──────────────────────────────────────────────────────────┤
│  小さな噴石の落下  降灰  28地域                          │
├──────────────────────────────────────────────────────────┤
│  １７日１５時から１８日９時までに噴火が発生した場合に    │
│ は、以下の方向・距離に降灰及び小さな噴石の落下が予想され │
│ ます。                                                   │
```

## 地震情報 (VXSE51/52/53/61)

**関数**: `displayEarthquakeInfo(info: ParsedEarthquakeInfo)`（`src/ui/earthquake-info-formatter.ts`）
**パーサ**: `parseEarthquakeTelegram()`

新デザイン言語（weather/津波系で確立したレスポンシブ TUI 列優先度モデル）を適用済み（2026-07 rollout）。旧 `telegram-type-label.ts` のローカル `earthquakeFrameLevel` / `getDisplayMode() === "compact"` 分岐（震度一覧）は撤去済み。compact 表示は summary パイプライン (token-builders) 側の責務で、この formatter は full 表示のみを持つ。

### 電文タイプ

| コード | 名称 |
|--------|------|
| VXSE51 | 震度速報 |
| VXSE52 | 震源に関する情報 |
| VXSE53 | 震源・震度に関する情報 |
| VXSE61 | 顕著な地震の震源要素更新のお知らせ |

### フレームレベル判定

外枠・タイトルの severity は `earthquakeFrameLevel(info)`（`src/engine/presentation/level-helpers.ts`）を唯一の入力とする（formatter 内の二重実装は撤去済み）。

| 条件 | レベル |
|------|--------|
| `infoType` = 取消 | `cancel` (ラズベリー) |
| 最大震度 ≥ 6弱 | `critical` (バーミリオン) |
| 最大震度 ≥ 4 | `warning` (オレンジ) |
| その他（震度3以下・VXSE52・取消以外） | `normal` (スカイブルー) |

フレーム前バナーは廃止済み（spec §8 R2-2）。severity はフレーム色（罫線種別・色）とタイトル行の `SEVERITY_LABELS` で表現し、`critical`/`warning`/`normal`/`cancel` いずれも frameTop より前には空行以外出力しない。

### 3 段 breakpoint

weather/津波系と同一の閾値（`decideDisplayMode()`、`responsive-table-engine.ts`）。

| 画面幅 | モード |
|--------|--------|
| < 120 | `ultra-narrow` |
| 120 - 159 | `standard` |
| 160+ | `wide` |

### 震度行テーブルの Tier 割当

震度分布は「震度」「地域数」「地域名」の3列テーブル（`renderResponsiveTable()`、行 = 震度階級ごとの group-by）。判断根拠: 「どの震度がどれだけの範囲で観測されたか」が意思決定情報 (Tier 1)、地域数は Tier 2、地域名の全文列挙は Tier 3。

| モード | 表示列 |
|--------|--------|
| ultra-narrow (<120) | 震度・地域名（地域数列は非表示） |
| standard (120-159) | 震度・地域数・地域名 |
| wide (160+) | 震度・地域数・地域名（地域名列の maxWidth を 100→160 に拡大） |

地域名列は `wrap: true`。本体セルの地域名は全地域を `, ` 結合して**全件そのまま表示**する（折りたたみ・「ほか N 地域」・`[詳細]` への逃がしは廃止 — 2026-07 wrap 全表示化）。列幅を超える分はセル内改行（複数物理行）で折り返され、地域数が多い行はテーブル内でその分だけ縦に伸びる。長周期地震動階級1以上の地域には `[長周期N]` を付記。

震度行テーブルの末尾サマリ（`[サマリ]` divider + 1行要約）は廃止済み（spec §8 R2-2）。震度段差は震度行テーブルの震度列（色 + NO_COLOR prefix）のみで判別する。

## 緊急地震速報 (VXSE43/44/45)

**関数**: `displayEewInfo(info: ParsedEewInfo, context?: EewDisplayContext)`（`src/ui/eew-formatter.ts`）
**パーサ**: `parseEewTelegram()`

新デザイン言語（weather/津波系で確立したレスポンシブ TUI 列優先度モデル）を適用済み（Phase 4b、2026-07 rollout）。旧 `getDisplayMode() === "compact"` 早期 return 分岐は撤去済み。compact 表示は summary パイプライン (`runDisplayPipeline`) / Studio `compactLine` 側の責務で、この formatter は full 表示のみを持つ。

### 電文タイプ

| コード | 名称 |
|--------|------|
| VXSE43 | 緊急地震速報（警報） |
| VXSE44 | 緊急地震速報（予報） |
| VXSE45 | 緊急地震速報（地震動予報） |

### フレームレベル判定

`eewFrameLevel(info)`（`src/ui/eew-formatter.ts` / `src/engine/presentation/level-helpers.ts` に同一実装が 2 箇所存在、Phase 4b で無変更）。

| 条件 | レベル |
|------|--------|
| `infoType` = 取消 | `cancel` (ラズベリー) |
| `isWarning` = true | `critical` (バーミリオン) |
| その他 | `warning` (オレンジ) |

### 3 段 breakpoint

weather/津波系と同一の閾値（`decideDisplayMode()`、`responsive-table-engine.ts`）。

| 画面幅 | モード |
|--------|--------|
| < 120 | `ultra-narrow` |
| 120 - 159 | `standard` |
| 160+ | `wide` |

### 予測震度テーブルの列セット (Tier 割当)

`renderResponsiveTable()` で描画し、`eewForecastColumns(mode, hasLg)` がモード別列セットを明示切替する（engine は列を自動で落とさないため）。

| モード | 表示列 |
|--------|--------|
| ultra-narrow (<120) | 震度・地域・状態（長周期列は省略、`[詳細]` へも逃がさない — spec §8 R2-4） |
| standard (120-159) | 震度・地域・長周期 (`hasLg` 時のみ)・状態 |
| wide (160+) | 震度・地域・長周期 (`hasLg` 時のみ)・状態 |

- **震度列**: `From≠To` の範囲予測は「4〜5弱」表記（`formatEewIntensityRange()`）。`To="over"` は「N程度以上」
- **地域列**: 全地域を名前として表示（省略しない、列自体が隠れることもない）。列幅を超える地域名はセル内 clip のみで `[詳細]` には回収しない（hidden-only 原則。§ 詳細ブロック参照）
- **長周期列**: 表示中の行に階級 1 以上が 1 つでもあるとき (`hasLg`) のみ表示。全行 null/0 なら列ごと省略。**ultra-narrow では列ごと省略し `[詳細]` にも回収しない**（高さ削減優先の裁定、spec §8 R2-4）
- **状態列**: badge 配列（単一 enum にしない）。「到達済」(`hasArrived`) / 「HH:MM:SS 到達予測」(地域別 `arrivalTime`、到達済でないとき) / 「PLUM」(`isPlum`) を優先順にスペース区切りで併記。**旧「主要動到達と推測される地域」独立セクションはこの列に吸収され撤去済み**
- 並び順: **To（悲観側）基準の震度降順**（`eewPessimisticIntensity(intensity, intensityTo)` をキーに、`intensityTo ?? intensity` 相当）。**一枚テーブル統合（Task 5）**により階級ごとの divider・ヘッダ繰り返しは廃止済み — `予測震度` labeled divider 1 本 + ヘッダ 1 回 + 全行を単一テーブルで描画する（階級境の細線 divider は入れない。震度列が各行にあるので読める）
- 件数制限: `getMaxObservations()` を維持。表示上限を超えた地域は**震度別の集約行 1 本**（`… 他 N 地域 (震度6弱: 28 / 震度5強: 38 …)`、悲観側震度の強い順、`intensityColor()` 着色、狭幅では ` / ` を折返し点に複数行へ畳む）にまとめる。旧方式（`[詳細]` ブロック全列回収 + `EEW_DETAIL_HARD_CAP=200` 打ち切り）は 2026-07-25 に撤去 — fold で隠した地域を 1 件ずつ複数行詳細に展開すると総出力が逆に膨らむため。全地域の内訳は EEW ログ（`eew-logger`、既定 ON）で復元可能
- 幅 40〜200 の全域で frame 幅保証（枠線はみ出しゼロ、`test/ui/eew-formatter-width-sweep.test.ts`）

### 震源詳細ブロック

上から: 震源地（diff 時「(変更)」+ **内陸/海域** `landOrSea` 併記、値があるときのみ）→ 発生時刻 + **検知時刻**（`arrivalTime`。**PLUM 時 (`isAssumedHypocenter`) は検知時刻を優先表示**し、発生時刻は仮定値のため「(仮定)」を付記）→ 位置・規模・深さ（diff 時「旧 → 新」）→ **精度行**（新設）。

精度行は震央・深さ・M の rank を JMA コード表ベースの人間可読ラベルで表示する（`buildEewAccuracyLine()`）。未知 rank は「不明(N)」形式で数値付き fail-open 表示（silent 欠落させない）。`accuracy` が undefined の電文（Accuracy 要素自体が無い）では精度行そのものを省略する。仮定震源要素 (PLUM) 時のグレーアウト分岐は維持しつつ、精度行・検知時刻を同ブロックに組み込む。

### 取消報

バナー（取消色）+ 取消文 + EventID + footer の最短構成。取消文は **`cancelText`（Body/Text 由来）を優先**し、無ければ固定文「この地震についての緊急地震速報は取り消されました。」に fallback する。VXSE45 型（Headline 空 + Body/Text）と VXSE43 型（Headline/Text + Body/Text 両持ち）の双方で cancelText が欠落しない。

### 表示構成 (上から順)

| セクション | 条件 | 内容 |
|-----------|------|------|
| バナー | 常に表示 | 3行の背景色バナー。取消=ラズベリー, 警報=赤系, 予報=黄系。`colorIndex` で色分け。震源地名をバナーテキストに含む。PLUM 時は装飾行 (1・3行目) が専用スタイル |
| テスト電文バッジ | `isTest = true` | ` テスト電文 ` (ラズベリー背景) |
| PLUM法ラベル | `maxIntChangeReason = 9` | `PLUM法 による予測震度変化` (ラズベリー) |
| ── 区切り ── | | |
| カード行 | 取消以外 | `{infoType}  │  最大予測震度 {N}  │  長周期階級 {N}  │  M{x.x}  │  深さ {N}km`。`activeCount ≥ 2` 時は infoType の前に `同時{N}件発生中` (オレンジ) を付記。`diff.previousMaxInt` がある場合は `最大予測震度 {旧} → {新}` に変化。幅不足時は生存優先度 (最大予測震度 > M > 深さ > 長周期) の低い部品から落ちる (clamp 経路) |
| ── 区切り ── | | |
| ヘッドライン | `headline` があり非取消 | 太字白 |

### 仮定震源要素時の制限

`isAssumedHypocenter = true` の場合、以下は非表示:
- カード行のマグニチュード・深さ
- 震源詳細の規模・深さ

代わりに検知時刻 (`arrivalTime`) を優先表示し、発生時刻には「(仮定)」を付記する。

### テーブルと列優先度（Tier 割当）

4 テーブルはそれぞれ独立した row 型・列定義を持つが、描画は地震/EEW と共有の `renderResponsiveTable()`（`responsive-table-engine.ts`）を使う（旧・津波専用 `renderTsunamiTable()` は撤去済み）。`[詳細]` への回収は `collectDetailForTable()` の **hidden-only**（その幅で完全に隠れた列のみ）方式。セル内 clip（`raw !== clipped`）は検知信号として ClipReport に残るのみで `[詳細]` には回収しない。

| テーブル | ultra-narrow (<120) | standard (120-159) | wide (160+) |
|---|---|---|---|
| 予報区 (forecast) | 区分・地域名・波高 | + 到達予想 (4列) | 4列 + 余裕幅 |
| 満潮・到達予想 (tide-stations) | 観測点・到達予想 | + 満潮時刻・地域名 (4列) | 4列 + 余裕幅 |
| 沖合観測 (observations) | 観測点・最大波高 | 5列全部 (センサー含む、wide と同一列順) | 5列全部 |
| 沿岸推定 (estimations) | 地域名・波高 | 3列全部 | 3列 + 余裕幅 |

判断根拠: 「どこに・どれくらいの高さが来る/来たか」が意思決定情報 (Tier 1)、到達時刻系が Tier 2。観測点・沖合観測は spec §8 R2-1 でセンサー種別 (計測手段) も standard 幅から表示するよう改訂 (ultra-narrow のみ `[詳細]` へ逃がす)。tide-stations は観測点別の到達予想が Tier 1 (自分の街への到達時刻が避難判断の核)、満潮時刻・親地域名が Tier 2。

満潮・到達予想テーブルは `stations` を持つ forecast Item が 1 つでもあるときだけ表示する (VTSE51 潮位観測点拡張。パーサが `Item/Station` の `Name` / `HighTideDateTime` / `FirstHeight/ArrivalTime` を取り込む)。行は予報区の severity 順 → 電文内の観測点順で flatten する。

「区分」列 (予報区テーブル) と「地域名」列 (満潮・到達予想テーブル、先頭列) は `mergeRepeated: true` を持つ。rows は kind ランク順 (予報区) / 予報区の severity 順 (満潮・到達予想) にソート済みで同一区分・同一地域が連続するため、2 行目以降のセルが空白になり縦の反復が間引かれる (spec §3.3)。

### 火山状態管理 (VolcanoStateHolder)

`VolcanoStateHolder` が alert 系電文 (VFVO50/VFSVii) の状態を追跡します。

- 複数火山の同時追跡に対応 (`volcanoCode` をキーとする Map)
- 取消報・解除・Lv1継続 → エントリ削除（通常状態復帰）
- REPL プロンプトに最もレベルの高い火山警報を表示
- `detail volcano` コマンドで全継続中火山警報を一覧表示

#### 配色 + tier prefix (displaySeverity)

| displaySeverity | 重大度 | 色 | tier prefix | 適用例 |
|------|------|------|------|------|
| officialL5 | 特別警報 (緊急安全確保) | 紫 `#A030A0` (bg-chip) | ★★ | 大雨/土砂/高潮 特別警報 |

| officialL3 | 警報 (高齢者等避難) | バーミリオン `#D55E00` | ☆ | 大雨警報、高潮警報 |
| officialL2 | 注意報 (避難行動の確認) | オレンジ `#E69F00` | △ | 大雨注意報 |
| officialL1 | 早期注意情報 | グレー `#84919E` | ○ | (VPWW では原則出ない) |
| nonLevelSpecial | 非対応 特別警報 | ダークレッド (bg-chip) | ◆◆ | 暴風/波浪/大雪 特別警報 |
| nonLevelWarning | 非対応 警報 | バーミリオン | ◆ | 暴風警報、洪水警報 |
| nonLevelAdvisory | 非対応 注意報 | オレンジ | △ | 雷/濃霧/乾燥/着氷 等 |

- **公式警戒レベル相当は大雨/土砂災害/高潮の 3 family のみ** (`officialL{N}`)。暴風・波浪・大雪・雷等は警戒レベル非対応のため `nonLevel*` 階級で扱い、**L 表記を付けない** (例: `★★ L5 大雨特別警報` vs `◆◆ 暴風特別警報`)。記号系も公式 (○△☆★★★) と非対応 (△◆◆◆) で分離し、NO_COLOR でも識別可能。
- L4-L5 / nonLevelSpecial / release は **bg-chip (色背景+白文字、統一幅)** で dark ターミナル可読性を確保。
- 優先順位 `DISPLAY_SEVERITY_RANK`: officialL5 > officialL4 > nonLevelSpecial > officialL3 > nonLevelWarning > officialL2 > nonLevelAdvisory > officialL1 > unknown > release (公式 > 非対応の tie-break)。

#### フレームレベル (描画)

`weatherCoreFrameLevel` (formatter ローカル): L5/L4/nonLevelSpecial → critical / L3/nonLevelWarning → warning / L2/nonLevelAdvisory → normal / L1/unknown → info / 取消・解除のみ → cancel。
※ **Phase C (2026-06-12)** で通知レベル (presentation.frameLevel = `weatherFrameLevel`) も同じ displaySeverity ベースに統合済み (Code 43/48/49 = officialL4 が warning → critical)。唯一の意図的な差は「解除のみ電文」: 表示=cancel 色 / 通知=info 静音 (従来仕様を維持)。
※ **通知音 (soundLevel) は表示と独立 (2026-06-12 レビュー決定)**: `weatherSoundLevel` / `weatherWarningTimeseriesSoundLevel` は parser が集合ベースで導出した `maxSoundLevel` (`computeMaxSoundLevel`: 全 Kind を `DISPLAY_SEVERITY_TO_SOUND_LEVEL` に写して最大) を引く。critical 音は特別警報級 (officialL5/nonLevelSpecial) のみで、officialL4 は表示 (フレーム色・バナー) critical のまま音だけ warning。VPWW55-61/VPWS50/VPWP50 すべてに適用 (気象警報・注意報系は通知項目が多いための音量配分)。**L4 と特別警報級の共存時は特別警報側 (critical) が勝つ (集合ベース判定、2026-06-12 共存エッジ解消)** — rank 1 点代表の `maxDisplaySeverity` 経由だと critical 音が warning に潰れていた (VPWP50 Code 41+50 共存が実例)。

#### display-layout.json によるブロックレイアウト調整

VPWW55-61 の表示ブロックは `display-layout.json` (theme.json と同じ設定ディレクトリ) で並び順と表示 ON/OFF を調整できる。

デフォルト:

```json
{
  "weatherCore": {
    "banner": true,
    "footer": true,
    "body": ["table", "unknown", "comments", "actionGuide"],
    "tableOverflowDetail": true,
    "allowHiddenUnknown": false
  }
}
```

| 項目 | 内容 |
|---|---|
| `body` | フレーム内ブロックの並び順。含まれないブロックは非表示 |
| `table` | 警報テーブル (severity 別) + こぼれ受け詳細。**必須** (外すとエラー) |
| `unknown` | 未知警報コードの安全網。外すには `allowHiddenUnknown: true` の明示が必要 |
| `comments` | 補足 (気象庁コメント) |
| `actionGuide` | 行動の目安 |
| `banner` / `footer` | ON/OFF のみ (並び替え不可) |
| `tableOverflowDetail` | テーブルのこぼれ受け詳細。false で抑制 (警告対象) |

バリデーションは「保存時 strict / 実行時 fail-safe」: 不正な config でも FlEq は止まらず、該当セクションをデフォルトに戻して起動ログに警告を出す。REPL の `layout` コマンド (path / reset / reload / validate) で管理できる。

タイトル行・取消表示・フレーム罫線は安全上の根幹のため固定 (変更不可)。

### フレームレベル判定 (Phase B: displaySeverity ベース)

### バナー発火条件 (G2)

| 状況 | バナー |
|------|--------|
| `maxDisplaySeverity` ∈ {officialL5, officialL4, nonLevelSpecial} | critical バナー (バーミリオン) |
| `maxDisplaySeverity` ∈ {officialL3, nonLevelWarning} | warning バナー (オレンジ) |
| 取消 (`infoType = 取消`) | cancel バナー (ラズベリー) |
| `maxDisplaySeverity` ∈ {officialL2, nonLevelAdvisory, officialL1, null} | **バナー無し** (frame 単独) |

バナーは 3 行構造 (EEW・南海トラフと同形)、本文は **部品優先度落とし** で組み立てる:

| 優先度 | 部品 | 例 |
|--------|------|-----|
| 1 (最重要・絶対残す) | tier 記号 + 種別 (L 後置注釈付き) | `★ 土砂災害 (L4)` |
| 2 | 地域 | `稚内市` |
| 3 | ピーク時刻 | `ピーク 5日夜のはじめ頃` |
| 4 (オプション) | 注釈 (主要種別など) | `(土砂災害)` |

幅が足りないとき部品 4 → 3 → 2 の順に削り、tier 記号 + 種別は最後まで残す
(目的: 「自分の地域に当たるか」「どの級か」をバナーから消さない)。
複数警報の組み立て (M1) は **maxDisplaySeverity ベース**:

| 状況 (N = 同 displaySeverity の種別数) | 本文 |
|---|---|
| N = 1 | `★ 土砂災害 (L4)　稚内市　ピーク 5日夜のはじめ頃` |
| N = 2-3 (officialL 系) | `★ 土砂災害・高潮 (L4)　稚内市　ピーク 5日夜のはじめ頃` |
| N ≥ 4 | `★ 土砂災害 (L4) ほか 3 件　稚内市　ピーク …` |
| 異 displaySeverity 混在 | **最高 displaySeverity 1 点のみ** バナーへ、下位はフレームに委ねる |

### 3 段階 breakpoint

ターミナル幅で表示モードが切り替わる。閾値は config (`weatherWarningStandardThreshold` / `weatherWarningWideThreshold`) で上書き可能。

| モード | width | 表内列 | 注意報 | 詳細ブロックに逃がす情報 |
|--------|-------|--------|--------|--------------------------|
| **ultra-narrow** | `< 120` (default) | Tier 1 (3 列) | チップ列 | 時刻枠 / ピーク / 基準到達 / Local / 未知 / Sentence |
| **standard** | `120 〜 159` | Tier 1+2 (6 列) | 通常テーブル | Local / 未知 / Sentence (clip 時例外) |
| **wide** | `≥ 160` (default) | Tier 1+2+3 (7 列) | 通常テーブル | Sentence のみ (clip 時は Local/未知 も) |

幅境界の `=` 条件は `<` で判定 (例: `width < 120` → ultra-narrow、`120 ≤ width` → standard 以上)。

| 入力 | 出力 |

### 罫線配色言語 (VPWW / VPWP50 共通、目視ゲート 5 巡で確定)

| 平常 (表示対象なし)・compactOnly fallback | フレーム全体 **白系の単色** |

(critical/warning フレームでは二重線 `═`)、罫線は白系。

### 詳細ブロック (`[詳細]`)

末尾に `╠ [詳細] ═══╣` ラベル付き divider (罫線白系、スタイルは frame styleLevel 準拠) を出し、その下に
**隠れた列の全文** + **Local 細分** + **未知 Code** + **CriteriaPeriod.Sentence** を
**種別@地域** 単位でネスト表示する。

書式:

```
╠ [詳細] ══════════════════════════════════════╣
║   ★ 土砂災害 (L4) @稚内市
║       時刻枠[1]: 朝-夕方 (3枠/9h)
║       時刻枠[2]: 終日 (1枠/24h)
║       ピーク: 5日夜のはじめ頃
║       基準到達: 21:00 〜 03:00 (翌) (6h)
║       Local: 稚内海岸 ほか1
║       未知: ?87
║       Sentence: 5日夜のはじめ頃から夜遅くにかけて警戒レベル4相当の予測
```

**`公式レベル` 行は廃止済み**: officialAlertLevel はテーブルの種別列 (`土砂災害 (L4)`) と級列 (★/☆) に既出のため、`[詳細]` での再掲は完全重複として削除した (2026-07-06、visual-gate 指摘対応)。

#### 採用ルール (clip 検知ベース)

- **clip 検知**: 表セルで `raw !== clipped` (全文が幅圧迫で切れた) なら **mode 問わず必ず detail に全文を出す**
- **全 window 走査**: 1 entry に複数 window がある場合 (TimeSeries 1 と 2 など) は `時刻枠[N]: ...` 形式で **全 window** を順に列挙
- **常時出す情報**: Local (`localAreaNames` が空でない時) / 未知 (`unknownCodes` が空でない時) / Sentence は mode 問わず常に出す
- **wide モード時の重複回避**: 備考列で完全に読める Local/未知 は detail から省略してよい

#### 優先度残留ガード (P1〜P4)

詳細ブロックの肥大化を防ぐため、以下のガードを設ける:

- **1 entry あたり最大行数**: ヘッダ行を除いて **最大 8 行** (`weatherWarningDetailMaxPerEntry`)
- **全 detail block の最大行数**: ヘッダ含めて **最大 60 行** (`weatherWarningDetailMaxTotal`)、超過時は `╠ [詳細] (N entry 省略) ═══╣` で打ち切り
- 判定は `wrapFrameLines` 適用後の **実描画行数** で行う (長 Sentence の wrap 膨張を考慮)
- 8 行に収まらないときは以下の優先度順で残し、低優先度から省略:
  - **P1**: clip された全文 (基準到達 / 時刻枠 / ピーク / 備考 等)
  - **P2**: Local 細分 / 未知 Code 標識 (安全情報)
  - **P3**: Sentence (複数あれば 1 件目のみ残し残りは `... ほか N 文省略`)
  - **P4**: 通常 window 情報 (clip 無しの時刻枠/ピーク/基準到達)
- それでも収まらないときは `... ほか N 項目省略` で打ち切り、ヘッダは絶対残す

#### stable entry id

`WeatherSeverityEntry` に stable id (`propertyType|areaName|displaySeverity|worstCode|localKey`) を持たせ、
`ClipReport` のキーをこの id にする。同一地域の Base/Local 並列や Code 違いが衝突しない。
**Phase B 変更点**: 3 セグメント目が旧 `severity` (3 段階) から `displaySeverity` (10 値) に変更。

### 未知 Code (二重表示)

安全上の理由から **2 箇所** に表示:

1. **テーブル内の備考列** (wide モードのみ): 該当行に `未知:?87`
2. **frame 末尾の独立ブロック** (全モード): `╠ ! 未知 Code ═══╣` divider 付き、全未知 Code の `(種別/地域/Code/timeRef)` を一覧

各未知 Code 行は `wrapFrameLines(level, line, width, 2)` で必ず折返し処理
(長い propertyType + areaName でも frame をはみ出さない)。

### compact モード (1 行表示)

### NO_COLOR / グレースケール対応

色が見えない環境でも tier 段差が読み取れるよう **3 重の冗長性** を確保:

1. **行内 tier prefix** (`★★` / `★` / `☆` / `△` / `◆◆` / `◆` / `?`) — 行単位で tier 自明
2. **ラベル付き divider** (`★ 危険警報 (L4)` / `◆◆ 特別警報` / `☆ 警報 (L3)` / `△ 注意報` / `[詳細]` / `! 未知 Code`) — テキストで段差を表現
3. **末尾の独立ブロック** — 警戒の根拠を明文化 (Local / 未知 Code / Sentence)

幅境界テストは全 fixture × `[60, 80, 119, 120, 139, 159, 160, 200]` で
`visualWidth(stripAnsi(line)) <= width` を vitest で必須保証する。

## 竜巻注意情報 (VPHW50, VPHW51)

**関数**: `displayTornadoAdvisory(info: ParsedTornadoAdvisory)`
**パーサ**: `parseTornadoAdvisory()` (VPHW50 = 通常発表 / VPHW51 = 目撃情報付き)
**FrameLevel**: 目撃情報あり (nonLevelSpecial)=critical / 通常発表 (nonLevelWarning)=warning / 発表地域なし=info / 取消=cancel

**Phase D (2026-06-12) 配色言語適用**。判定は parser 段の `displaySeverity` / `soundLevel` を単一真実源とする (`resolveTornadoSeverity`)。`tornadoFrameLevel` は表示、`tornadoSoundLevel` は音を引く。

- 目撃情報あり (sightingAreas あり、または目撃電文で地域抽出に失敗したフェイルセーフ) = nonLevelSpecial → **表示 critical**
- 通常の発表 (activeAreaCount > 0) = nonLevelWarning → warning
- 発表地域なし = info / 取消 = cancel

### 配色 (colored frame + severity バナー)

- **colored frame**: 上辺 + タイトル罫線 = `displaySeverity` 色、本文・フッタ = 白系 (`#e8e8e8`)、取消 = フレーム全体 release 単色、平常 (対象なし) = 白単色。

## 気象防災速報 (VPBS50)

**関数**: `displayWeatherBriefing(info: ParsedWeatherBriefing)`
**パーサ**: `parseWeatherBriefing()` (線状降水帯 / 記録的短時間大雨 / 短時間大雪 等)
**FrameLevel**: 線状降水帯発生 / 記録雨 (nonLevelSpecial)=critical / 線状降水帯予想 / 短時間大雪 (nonLevelWarning)=warning / 対象なし=info / 取消=cancel

## 天候情報 (VPZI50, VPCI50)

**関数**: `displayClimateInfo(info: ParsedClimateInfo)`
**パーサ**: `parseClimateInfo()` (VPZI50/VPCI50 共通)
**FrameLevel**: 取消=cancel、その他=normal (1〜数ヶ月の気候統計情報のため一律。早期天候情報と同じ方針)

2 電文タイプは同じパーサ・処理パスを共有します:
- VPZI50: 気象庁本庁が出す全般スケールの天候情報 (長期間の高温・少雨等)
- VPCI50: 管区・地方気象台が出す地方スケールの天候情報 (梅雨入り/明け等の季節イベントを含む)

フレームタイトルは `controlTitle` 由来で「全般天候情報」/「地方天候情報」が出し分けされます
(controlTitle 空時のフォールバックは「天候情報」)。

### 表示構造

| セクション | 条件 | 内容 |
|----------|------|------|
| タイトル行 | 常時 | `controlTitle` (太字) + `infoType` + severity ラベル |
| サブタイトル | `title !== controlTitle` | `title` (例:「梅雨の時期に関する東北地方気象情報」) |
| ヘッドライン | `headline` あり | `[ヘッドライン]` 見出し + 改行ごとに整形 |
| 対象地域 | `targetArea` あり | `[対象地域]` + 地域名 |
| 本文ブロック | `bodyTexts` あり | `[本文]` + `▸ 概況` / `▸ 今後の見通し` / `▸ 防災事項` 等。各ブロック末尾に `対象: <地域名>` (targetArea と同一 code の地域はフィルタ) |
| 季節イベント | `seasonEvents` あり (VPCI50 のみ) | `▸ 梅雨明け <日付> (平年 … / 昨年 …)` + `対象: <地域名>` (本文ブロックと同じく targetArea と同一 code はフィルタ) |
| 観測点別気候値 | `stations` あり | `[観測点別気候値] <期間ラベル>` + 観測点ごとに気温 (平年差/平年値) / 降水 (平年比/平年値)。数値列は全観測点スキャンの右揃えで列を揃える (下記「観測点別気候値の整形」参照) |
| 末文 | `comment` あり | `[末文]` + Comment 本文 |
| フッター | 常時 | 電文種別 / 発表時刻 / 発表元 |

### 季節イベント (seasonEvents) の表示

VPCI50 の `EventDatePart` (梅雨入り/梅雨明け等) 由来。VPZI50 では常に空。

- **日付あり**: `▸ 梅雨明け ７月１９日ごろ (平年 ７月２０日ごろ / 昨年 ８月１日ごろ)`
- **日付なし (発表なし)**: `Date` 欠落 = 「梅雨明けの発表を行わないこととした」ケース。
  `▸ 梅雨明け （発表なし） (平年 … / 昨年 …)` と表示する (「日付不明」はミスリードのため不採用)
- **地域表示**: 各イベントの `areas` のうち targetArea と異なる細分のみ `対象: 東北北部` の形で表示。
  targetArea と同一 code (例: 関東甲信 fixture の 10300) の場合は地域行を出さない

### 観測点別気候値の整形

- 気温: `気温  9.2℃ +1.6℃` (平年差は符号付き。負値は全角マイナス `−`、ゼロは `±`)
- 降水: `降水 19.5mm 平年比 23%` (平年比は符号なし)
- 平年値: type 違いの兄弟要素 (例: `降水量日別平滑平年値合計`) があれば `降水 132.5mm (平年 153.0mm)` の形で添える (気温側も同型)
- **列揃え**: 全観測点をスキャンして各数値フィールドの最大視覚幅を事前計算し、右揃えパディングで「気温」「降水」「平年比」の開始桁を揃える。観測点名は `max(8, 実最大幅)` の `visualPadEnd`
- **小数桁の列内統一**: 電文原文は同一表内で小数桁が揃っている (例 `58.0`) が parseFloat で `.0` が落ちるため、列内最大小数桁に揃えて復元する (`58` → `58.0mm`)
- **全フィールド null の観測点** (「表題」型など): 1 行 1 局の縦積みにせず `水戸 / 宇都宮 / 前橋` のようにスラッシュ区切りで連結する (折返しは wrap の " / " delimiter に任せる)
- 期間ラベル (`MeteorologicalInfo > Name`、例「６月２日から７月１８日まで」) があれば見出しに添える

```
│ [観測点別気候値] ６月２０日から８月４日まで                                  │
│   青森     降水 132.5mm (平年 153.0mm)                                       │
│   秋田     降水 283.0mm (平年 265.4mm)                                       │
```

### compact モード

severity ラベル + `controlTitle` + 対象地域名 + `title` + `観測点 N地点` を 1 行で表示。
取消時は `controlTitle` + `取消`。

### 取消発表

`infoType = "取消"` のときは `${controlTitle}は取り消されました` の 1 行のみ表示し、
本文・季節イベント・観測点は抑制する。FrameLevel は `cancel`。

## 気象解説情報 (VPCJ51, VPZJ51, VPFJ51, VMCJ53-55)

**関数**: `displayWeatherExplanation(info: ParsedWeatherExplanation)`
**パーサ**: `parseWeatherExplanation()` (VPCJ51/VPZJ51/VPFJ51/VMCJ53-55 共通)
**FrameLevel**: 取消=cancel、その他=normal (一律)

※ **Phase D (2026-06-12)**: formatter を colored frame プリミティブへ置換 (白単色 / 取消 = release 単色)。表示内容は不変で、一律 normal (取消以外) は契約テストで固定化された (Headline キーワード解釈による昇格は不採用 — レビュー決定)。早期天候情報 (VPAW51) も同じく colored frame 化 + 一律 normal 契約テスト固定で、表示内容は不変。

6 電文タイプは全て同じパーサ・処理パスを共有します:
- VPCJ51: 地方気象台が出す地方スケールの気象解説情報
- VPZJ51: 気象庁本庁が出す全般スケールの気象解説情報
- VPFJ51: 気象庁本庁が出す府県スケールの気象解説情報（観測実況中心）
- VMCJ53/54/55: 全般/地方/府県の気象解説情報（潮位）— 大潮・副振動等。`tidal` (TidalLevelPart) を持つことがある

フレームタイトルは `controlTitle` 由来で「地方気象解説情報」/「全般気象解説情報」/「府県気象解説情報」が出し分けされます。
台風電文の `InformationTag.Code` は台風コード (例 `TC2510`) のため、
情報タグバナーから除外される (parser 側で fixup)。

### 表示構造 (normal 発表)

| セクション | 条件 | 内容 |
|----------|------|------|
| タイトル行 | 常時 | `controlTitle` (太字) + `infoType` + severity ラベル |
| サブタイトル | `title !== controlTitle` | `title` (例:「全般気象解説情報（台風第１０号）」) |
| 情報タグバナー | `informationTags` あり | キーワードを「・」で連結 (台風コード除外済み) |
| 対象地域 | `targetAreas` あり | 地域名をカンマ区切りで列挙 |
| ヘッドライン | `headline` あり | 改行ごとに整形 |
| 本文セクション | `sections` あり | `▸ 概況` / `▸ 防災事項` / `▸ 付加情報` 等。連続する同一 sectionType の sections は 1 グループとして divider + 見出しを先頭で 1 回だけ出す (VMCJ55 89_01: 観測実況 Property の Text 解説 + 気象要素の 2 本で見出しが重複しない)。間に別 type が挟まる非連続の同一 type は文書順を尊重して見出しを再表示 |
| 潮位 (VMCJ53-55) | `tidal` あり | 値を対応セクション (`▸ 観測実況` / `▸ 予想: …`) 直下へ統合。対応先が無い場合のみ standalone `▸ 潮位実況` / `▸ 潮位予想` (TidalLevelPart) |
| 予想 (TimeSeriesInfo) | `forecast` あり | 系列ごとに `▸ 予想: <Element>` + テーブル |
| フッター | 常時 | 電文種別 / 発表時刻 / 発表元 |

### 予想時系列テーブル (TimeSeriesInfo)

VPZJ51・VPFJ51 は VPCJ51 にない予想 `forecast` を持つことがあります。系列 (`series`) ごとに
intro 散文 → テーブルを描画します。テーブルは 2 種類:

- **events 系列** (線状降水帯予想など): 2 列 `[地域 | 期間]`。
  `regionLabel` あり時は地域に `(四国地方)高知県` のような接頭辞を付与。
- **metrics 系列** (定量予測): 1 + N 列 `[地域 | <timeName1> | <timeName2> ...]`。
  列ヘッダ末尾に系列 `unit` を `(℃)` 等で付与。セルは subType + value + condition。
  全セル欠測なら `−` に畳む。

テーブルは `pushFrameTable(..., indent=6)` で描画し、セクション見出し (`▸ 予想`、2 スペース)
配下の本文 (4 スペース) よりさらに 1 段下げて、テーブルであることを視覚的に分離します
(見出しより左に飛び出さない)。

intro 散文のうち `Text type="時系列解説"` は本数で扱いが変わります:

- **同一 Property 内に複数** = TimeDefine 別キャプション (例: VMCJ55 89_02 の
  「４日に予想される満潮時刻…」×7、VPZJ51 の「２９日に予想される最大風速…」×2)。
  日付情報は metrics テーブルの列見出し (timeName) / 潮位予想の `[timeName]` と
  完全重複するため intro に積まない (繰返し行だけのセクションになるのを防ぐ)
- **単一** = セクション導入文 (例: VMCJ55 89_01 の「次の満潮・干潮時刻は、以下のとおりです。」)
  として意味があるため intro に残す

### 観測実況セクション (VPFJ51)

VPFJ51 の観測実況セクションには、各地域の最新観測値が記載されます。
セクション内の見出しに応じて「雨の実況」「風の実況」などの副見出しの下に観測値が表示されます。
「観測史上１位」など記録更新情報は、該当する観測地点のデータ行に注釈として付与されます。

インデント階層は 見出し (2) < 副見出し (4) < 配下行 (6)。副見出し・観測点行も
wrap 経由で描画され、フレーム幅を超える場合は hanging indent 付きで折り返されます。

例:
```
  ▸ 観測実況
    雨の実況 (降水量（アメダスによる速報値）)
      ６日１４時から７日１６時までの降水量（アメダスによる速報値）
      三宅島  52mm  ※観測史上１位  (16:00)
    風の実況
      三宅島  北東 25m/s  ※観測史上１位  (11:57)
```

### 潮位セクション (VMCJ53-55)

気象解説情報（潮位）の `TidalLevelPart` の値は、「以下のとおりです」と述べる対応セクションの
直下に統合して描画します (目視ゲート 2 巡目 指摘 #3):

- **実況** (副振動の高さ・周期等): 本文セクションに `sectionType="観測実況"` があれば、
  その最後の section の直下に値行を挿入する
- **予想** (満潮・干潮時刻等): 予想系 TimeSeriesInfo の文書順インデックス
  (`WeatherExplanationTidalEntry.seriesIndex` ↔ `ForecastTimeSeries.sourceIndex`) で突き合わせ、
  一致する **空 series** (TidalLevelPart はメトリクスとして認識されず metrics/events が無い) の
  `▸ 予想: <Element>` 見出し + intro の直下に値行を挿入する

対応先が無いエントリ (観測実況 section が無い / seriesIndex 不一致 / forecast が raw fallback) は
フォールバックとして従来どおり standalone `▸ 潮位実況` / `▸ 潮位予想` 見出しで描画します
(空グループは出さない)。統合・standalone とも行形式は同一で、
1 行 = `観測点名  [timeName] (levelType 補助) Sentence`:

- **観測点名** (太字白): Item 直下 Station の Name (例「苫小牧東（港湾局）」)
- **[timeName]** (グレー): TimeDefines を refID 解決した期間名 (例「[９月１９日]」、予想のみ)
- **levelType 補助** (白): `jmx_eb:TidalLevel@type` が「満潮潮位」/「干潮潮位」で、かつ Sentence に
  「満潮」/「干潮」の語が無いときだけ「満潮 」/「干潮 」を補う。
  89_02 型 (Sentence が「０１時０１分　５０センチ」形式) で満潮/干潮の区別を表示するための補助で、
  89_01 型 (「満潮時刻　…」) では二重表記になるため出さない。
  「副振動の山から谷の高さ」のような長い type も補助しない (行を支配して読みにくく、ヘッドライン・概況に説明があるため)
- **Sentence** (白): 電文の表示用文字列をそのまま

例 (VMCJ55 副振動 89_01、統合後):
```
├──────────────────────────────────────┤
│   ▸ 観測実況                          │
│     観測された海面昇降の山から谷の高さの最大値の発生時刻と高さ及び周期（速報値） │
│     苫小牧東（港湾局）  １９日１２時２０分ごろ　約８０センチ　約６０分 │
├──────────────────────────────────────┤
│   ▸ 予想: 次の満潮・干潮時刻          │
│     次の満潮・干潮時刻は、以下のとおりです。 │
│     苫小牧東（港湾局）  [９月１９日] 満潮時刻　１９日１７時０２分 │
│     苫小牧東（港湾局）  [９月１９日] 干潮時刻　１９日２３時４０分 │
```

89_02 型 (千葉・大潮) では `▸ 予想: 予想される満潮時刻及び平常時の潮位（標高で表示）` の
直下に `銚子漁港  [７月　４日] 満潮 ０１時０１分　５０センチ` のような行が続く。

## 熱中症警戒アラート (VPFT50)

**関数**: `displayHeatAlertInfo(info: ParsedHeatAlertInfo)`
**パーサ**: `parseHeatAlert()`
**FrameLevel**: 取消=cancel、題名に「特別警戒」を含む=critical (フェイルセーフ昇格)、通常の発表=warning

環境省・気象庁が共同で発表する暑さ指数 (ＷＢＧＴ) ベースの注意喚起電文です。
Body は `Notice` + `Comment/Text` の平文のみで構造化データを持たず、Headline.Text は実電文で常に空です。
このため表示 headline / 通知 body は本文先頭文 (`extractLeadSentence`) を合成して使います。

- 対象府県は Head.Title (例:「埼玉県熱中症警戒アラート」) から抽出 (`targetAreaName`)
- 題名に「特別警戒」を含む電文 (環境省の特別警戒アラート級が同型で配信された場合のフェイルセーフ) は
  表示 critical へ昇格。**音は warning 止まり** (critical 音 = 特別警報そのもののみ、の原則)

### 配色言語

| 状態 | フレーム全面 (外枠・本文罫線・フッタ) | バナー |
|------|------|------|
| 通常 (warning) | nonLevelWarning 色 | なし |
| 題名昇格 (critical) | nonLevelSpecial 色 | `◆◆ <title>` (nonLevelSpecial 色面) |
| 取消 (cancel) | release 単色 | `▼ 取消 熱中症警戒アラート` (release 色面) |

## サマリーライン (compact 表示)

**関数**: `renderSummaryLine(event: PresentationEvent, maxWidth?: number)` (`src/ui/summary/summary-line.ts`)

compact モード、focus 不一致時の dim 表示、およびユーザーテンプレート未指定時のデフォルト1行表示で使用されるトークンベースの幅適応表示。

### トークン構造

各電文は `SummaryToken[]` に分解される。各トークンは以下の属性を持つ:

| 属性 | 型 | 説明 |
|------|-----|------|
| `text` | `string` | 表示テキスト (chalk 着色済み) |
| `shortText` | `string?` | 幅不足時の短縮テキスト |
| `priority` | `0-4` | 優先度 (0=最高、常に表示) |
| `dropMode` | `"never" \| "shorten" \| "drop"` | 幅不足時の挙動 |

### 幅適応アルゴリズム (drop/shorten)

1. 全トークンの `preferredWidth` + セパレータ (`"  "`, 2文字) の合計が `maxWidth` 以下 → そのまま結合
2. 超過時: priority 4 → 3 → 2 の順で `dropMode: "drop"` のトークンを削除
3. まだ超過: `dropMode: "shorten"` のトークンを `shortText` に置換

priority 0 のトークン (severity ラベル、主要識別子) は常に表示される。

### 表示例

```
[緊急] EEW警報  #1  宮崎県南部  震度6弱  M6.8
[情報] 震源・震度に関する情報  千葉県東方沖  M4.2  震度3  津波なし
[取消] EEW取消  #1  豊後水道
```

## 常設ディスプレイ: テロップ (TickerLane)

**関数**: `buildTickerSentence(event: PresentationEvent)` (`src/engine/display/ticker-sentence.ts`)、気象は `analyzeWeatherTickerFacts` + `buildWeatherTickerSentence` (`src/engine/display/weather-ticker-facts.ts`) 経由。**コンポーネント**: `display/frontend/src/components/TickerLane.svelte`。

サーバ側が `PresentationEvent` を読める一文 (`tickerSentence`) に文章化し、`tickerCategory` (種別ラベル) と併せて protocol (`DisplayEventDtoV1`) に載せて配信する。

- **文体**: EEW・津波は体言止め・句点なし (例: 「宮崎県南部で震度6弱を観測」)。それ以外の全ドメインは文末に句点を付ける。`[警告]` 等の CLI 接頭辞は含めない (重大度は role 色とラベルが担う)
- **種別ラベル**: レーン左端に固定枠 (`.ticker-label`, 最大 14em) で表示し、本文行に連動して切り替わる。VPWS50 (全国集約) のみ「気象警報・注意報（全国集約）」と単県電文と区別する
- **地域集約**: `formatPrefectureList` が地域名を都道府県単位に集約し、3件までは列挙、超過分は「代表3件など12都県」のように県数を添える。気象警報のテロップは市町村層ではなく府県予報区層 (`pickPrefectureLayer`) を由来にする (市町村層だと都道府県接頭辞が失われ集約できないため)
- **注意報等の下位ランク**: 主要画面 (WeatherAlertCard 等) には出さない下位ランクも、テロップには文章として流す (`analyzeWeatherTickerFacts` は displaySeverity を問わず layer 全体を拾う)
- **続報版管理 (`groupKey`)**: テロップの続報は `makeGroupKey` (`src/engine/display/project-event.ts`) が付与する `groupKey` 単位で最新 1 件へ畳まれる (フロント `foldCatalog` / `enqueueJob` 置換、サーバ `sweepTicker`)。weather は 2 系統: VPWS50 = 気象庁の全国集約単一ストリーム (集約定時通報) なので安定シングルトン `weather:vpws50`、VPWW55-61 = 府県気象台ごとの警報カテゴリ別ストリーム (VPWW55=大雨 / 56=土砂 / 57=高潮…) なので `weather:{type}:{publishingOffice}`。後者は同一府県・同一カテゴリの続報のみ 1 本化し、異なる府県・カテゴリは別キーで共存する。groupKey が無いと頻発する VPWS50 の続報が別エントリとして上下 2 レーンに同時に載る (二重表示の原因)
- **色 (severity role) と優先度・音の分離**: role 色は `summaryRole` (`project-event.ts`) が決める。weather の色は「現在の全国集約の最大 severity」(`PresentationEvent.displaySeverity`、`process-weather` が `weatherFrameLevel` から導出) を使い安定させる。VPWS50 の無変化電文 (`isUnchanged && !shouldRecap`) は静音化のため `frameLevel` / `soundLevel` が `info` に降格するが、色 (`displaySeverity`) はその巻き添えを受けず集約 severity のまま (警報が出ている間は警報色を保ち、灰化しない)。テロップ優先度 (`tickerPriority`) と通知音は従来どおり `frameLevel` 由来で、無変化は割り込まず静音のまま。unsafe (layer 不在等) 時の色は集約 severity 素通し (`frameLevel` は警告フロアへ昇格するが色は実状況を反映)。※ この `displaySeverity` は color 用 `FrameLevel` で、weather formatter 節の DisplaySeverity (officialL5/L4/nonLevelSpecial…、`weather-warning-level.ts`) とは別概念
- **割込み優先度 (`ticker-schedule.ts` `assignLanes`)**: 走行中テロップへの即時割込みは **high ランクの候補のみ** 許可する。mid はキューで待ち、走行中の文が流し終わって (scroll 完了 → レーン idle) 次割当されるのを待ってから入る。キュー内の取り出し順は「ランク高い順 → 同ランク到着順 (seq 昇順)」の FIFO。これは気象注意報 (low) の一斉着信時に警報 (mid) が次々割込んで注意報が読めないまま消える (2 回目以降 5 分保留で実質消失する) 問題への対処 (2026-07-13)。ただし同一 `groupKey` の続報 (取消・優先度上昇) は「別テロップの割込み」ではなく「同じ話の更新」なので、`mustReplaceImmediately` により従来どおり即差し替える。
- **フォールバック**: `tickerSentence` が欠落する場合 (新フロント + 旧サーバの移行期など)、`TickerLane.displayText()` が `summary.text + " ▪ " + tickerDetail` の従来連結表示にフォールバックする。サーバ側でも文章化に失敗した場合は `headline` ベースの最小一文 (`fallbackTickerText`) に落ちる (旧来の summary 連結 + 地域羅列のダンプ表示には戻さない)

### Tips / 緊急時の防災情報テロップ

電文由来のテロップが 0 件かつ待機モード (緊急パネルなし) のとき、CLI の待機中 Tips のうち知識系カテゴリのみ (`commands-basic` / `commands-advanced` / `tool-internals` を除外) がテロップに流れる (`display/frontend/src/lib/tips-feeder.svelte.ts`)。

- **連続供給**: 条件成立で即1本流し、以降は Ticker の走行完了通知 (`onIdle` → `notifyIdle()`) を受けてすぐ次の1本に差し替える (2026-07-12 改訂、間欠タイマーは廃止)。帯が空白で待つ時間はない
- **見た目**: 文頭の `Tip: ` prefix は除去され、チップ (左端ラベル) は「豆知識」・中立色 (role `info`)・priority `low`
- **供給元**: サーバの `GET /tips?context=standby|emergency` (シャッフル済みデッキ、`src/engine/display/display-tips.ts`)。省略時は standby、未知 context は 400。取得結果は `no-store` で返す。
- **電文優先**: 電文テロップが現れたら以後の Tips 供給は止まり、走行中の Tip は既存スケジューラが走り切らせる
- **目視確認**: `preview.html#ticker-tips` シナリオ、または MotionCatalog テロップタブの「Tip を投入」ボタン

緊急 context の `emergency-guidance` は、確認済みの防災情報 10 件だけを別デッキで配る。各本文はサーバ側で id・出典・確認日・失効日・許容 hazard を管理し、ブラウザへは id/text/hazards のみ渡す。

緊急 companion は lane 1 専用で lane 0 へ fallback しない。同 priority では実電文を先に取り、critical tier・未知 tier/hazard では既定で無効にする。さらに emergency session ごとの最大 1 回と 120 秒 cooldown を満たす場合だけ出せる。feeder は context 世代、AbortController、timeout で旧 context の取得結果を破棄する。

## ミニマップ表示

**関数**: `renderMinimapForEvent(event: PresentationEvent)` (`src/ui/minimap/minimap-renderer.ts`)

12行 x 13列の ASCII グリッドで日本全国47都道府県の震度・津波警報状態を俯瞰表示する。

### グリッド仕様

| 項目 | 値 |
|------|-----|
| 行数 | 12 (`GRID_ROWS`) |
| 列数 | 13 (`GRID_COLS`) |
| セル幅 | 6文字 (`"AA:xx "`) |
| 全体幅 | 78文字 |

各セルは `{都道府県2文字コード}:{震度/津波略称}` 形式。データなしの都道府県は `AA:..` (dim表示)。

### 表示条件 (`shouldShowMinimap`)

| 条件 | 判定 |
|------|------|
| ターミナル幅 | 80文字以上必須 |
| 取消電文 | 表示しない |
| 地震情報 | 震度ランク ≥ 4 または 観測地域 ≥ 4 |
| EEW | 予報区域が1つ以上 |
| 津波 | 予報区域あり かつ frameLevel が critical/warning/normal |
| 長周期地震動 | 震度ランク ≥ 4 または 観測地域 ≥ 4 |
| 火山・テキスト系等 | 表示しない |

### 凡例

グリッド左上の空白エリアに震度色と津波略称の凡例が重畳表示される:

- 震度: `1` `2` `3` `4` `5-` `5+` `6-` `6+` `7` (各震度色で着色)
- 津波: `MJ` (大津波警報、redBright) / `WN` (津波警報、red) / `AD` (注意報、yellow)

### 都道府県コード

47都道府県を2文字のアルファベットコード (`HK`=北海道, `AO`=青森, ..., `OK`=沖縄) でマッピング。`mapAreaToPref()` が地域名 → 都道府県コードの変換を行う。

彩度・輝度を抑制した夜間向け表示モード。全色の RGB 値を 50% に減光する。

### 減光対象外ロール (6件)

以下のロールは critical 級の危険色であり、夜間でも視認性を維持するため減光対象外:

| ロール名 | 用途 |
|---------|------|
| `frameCritical` | critical フレーム罫線 |
| `tsunamiMajor` | 大津波警報 |
| `eewWarningBanner` | EEW 警報バナー |
| `volcanoFlashBanner` | 噴火速報バナー |
| `intensity6Upper` | 震度6強 |
| `intensity7` | 震度7 |

### 減光の仕組み

- `dimRgb()`: 各 RGB チャンネルを `Math.round(value * 0.5)` で半減
- パレット色とロールスタイルの両方に適用
- 元のテーマを変更しない純粋関数 (新しい `ResolvedTheme` を返す)

### 有効化方法

- CLI: `fleq --night`
- REPL: `night on` / `night off`
- Config: `nightMode: true`

## カラーテーマカスタマイズ

表示色は `theme.json` ファイルを編集することでカスタマイズできます。テーマ管理は `src/ui/theme.ts` で定義されています。

### theme.json の配置場所

Configファイルと同じディレクトリに配置します:

- **macOS**: `~/Library/Application Support/fleq/theme.json`
- **Linux**: `~/.config/fleq/theme.json`
- **Windows**: `%APPDATA%\fleq\theme.json`

`XDG_CONFIG_HOME` が設定されている場合はそちらが優先されます。

### theme.json の構造

```json
{
  "palette": {
    "gray": "#84919E",
    "sky": "#56B4E9",
    "blue": "#0072B2",
    "blueGreen": "#009E73",
    "yellow": "#F0E442",
    "orange": "#E69F00",
    "vermillion": "#D55E00",
    "raspberry": "#CC79A7",
    "darkRed": "#7A1E00"
  },
  "roles": {
    "frameCritical": "vermillion",
    "intensity7": { "bg": "darkRed", "fg": "#FFFFFF", "bold": true },
    "hypocenter": { "fg": "yellow", "bold": true }
  }
}
```

- **palette**: 9色のベースカラーを HEX (`#RRGGBB`) で定義。変更したい色だけ記述すればOK
- **roles**: 各表示要素のスタイルを定義。文字列ならパレット名 or HEX を前景色として使用。オブジェクトなら `fg`/`bg`/`bold` を個別指定可能

### ロールスタイルの指定方法

| 形式 | 例 | 説明 |
|------|-----|------|
| パレット名 (文字列) | `"sky"` | パレットの色を前景色として使用 |
| HEX (文字列) | `"#FF0000"` | HEX値を前景色として使用 |
| オブジェクト | `{ "fg": "sky", "bg": "#000", "bold": true }` | fg/bg/bold を個別指定 |

`fg` と `bg` にはパレット名または HEX 値を指定できます。

### REPL `theme` コマンド

| コマンド | 動作 |
|----------|------|
| `theme` | テーマ概要（パレットスウォッチ・パス・カスタマイズ有無）を表示 |
| `theme path` | theme.json の絶対パスを表示 |
| `theme show` | 全パレット色・全ロールスタイルを一覧表示 |
| `theme reset` | デフォルト theme.json を書き出す (確認あり) |
| `theme reload` | theme.json を再読込して反映する |
| `theme validate` | theme.json を検証して問題点を表示 |

### カスタマイズ手順

1. `theme reset` でデフォルトの theme.json を生成
2. theme.json をエディタで編集（palette の HEX値や roles のスタイルを変更）
3. `theme reload` で変更を反映
4. `colors` コマンドで変更後の色を確認

theme.json を削除すると自動的にデフォルトテーマにフォールバックします。
