# 待機画面 従来フォーマット改良

グリッドレイアウト凍結（2026-08-15、`freeze/standby-grid-2026-08-15`）を受けた従来フォーマットの改良仕様。比較モック 13 巡（`display/frontend/src/preview/LegacyImprovedMock.svelte`、`preview.html?nav=0&legacyMock2=4|7|max[&ladder=0..3]#legacy-improved-mock`）でご主人の目視 GO を得た確定形を本実装へ写す。

本 spec は品質メタ見直し（2026-08-15 合意）の第一号適用例であり、§9 の受け入れ条件は Oracle 欄（主張・基線・反証条件・Oracle と証跡・判定者と時点）を持つ。

## 1. 目的と主張

- **主張**: 全 active hazard を無操作・無ページングで常時表示しながら、平時は時計ランドマークを画面中心に保ち、災害多発時も文字サイズを潰さずに全件を収容する。
- **基線**: 現行 main の待機画面（corner スタック＋overflow summary）と、凍結済みグリッド実装。
- **反証条件**: 実機（Pi・720p〜1080p）の目視で「基線より読みにくい」「配置が予測できない」とご主人が裁定した場合、該当変更単位を差し戻す。
- **Oracle と証跡**: 機械層は §9.1（テスト・実測ゲート・診断属性）。利用価値層はご主人の目視 packet 裁定（§10）。
- **判定者と時点**: 実装前=モック 13 巡で裁定済み。実装後=変更単位ごとの目視 packet と、main 合流前の最終目視。

## 2. 固定 tier（見る場所は動かない）

| tier | domain | 形式 |
|---|---|---|
| 左列（先頭固定） | 津波（TsunamiStandbyBanner）→ 最新地震（長周期 rider・リプレイ差し替え） | 現行形式そのまま |
| 右列 | 気象警報（竜巻 rider）→ 河川洪水 → 台風 → 火山 → 熱中症 | 現行形式（気象警報のみ §6 の改修） |
| 中央（時計ランドマーク） | 時計・受信統計・今日あった地震 | §3 |
| 下部帯 | 南海トラフ | ticker 直上に接地・左右 edge inset |
| 非表示 | unknown（未対応電文系） | 画面から排除。受信はログに記録し観測可能性を保つ |

- 左列の先頭は常に津波→地震。それ以外のカードは §4 のソルバが左右いずれにも配置できる。
- 中央受け皿（時計退避後）へ移動できるのは **気象警報・河川洪水・台風・火山** のみ（中央資格）。熱中症は左右のみ。地震・津波系は常に左。

## 3. レイアウトと時計ランドマーク

- 3 列等幅グリッド `repeat(3, minmax(0, 1fr))`。間隔は縦横 1 トークン。
- 側列カード幅は `min(30rem, track)` で track 内中央寄せ。中央に置かれる要素（時計クラスタ・受け皿カード）はすべて 36rem 規格。
- **時計は viewport 縦横中央に絶対固定**。フォントは列幅追従 `clamp(72px, 16cqw, 160px)`、秒・日付は比例。1920×1080 / 1512×982 の双方で秒が欠けない。
- 平時の中央クラスタは「時計 → 受信統計 → 今日あった地震 → 南海帯上辺」の 3 区間を実測等間隔。
- 南海トラフ帯は ticker 領域の直上に gap なしで接地し、左右に edge inset を持つ（テロップと一体化させない）。帯の実測高は全列の容量から差し引く。
- 時計退避（stage 2/3）後は、**全列（左右・中央）ともカードを縦中央揃え**にする。

## 4. 実測 2 パスと左右優先ソルバ

- 高さは算術推定ではなく**実 DOM 同期測定**で得る: マウント直後に測定棚（本表示と同幅・同 CSS の非表示棚。side 幅と中央 36rem の二重測定）を同期 read し、1 回の再描画で配置を確定する。rAF 連鎖は使わない（headless 停止実績があるため）。
- 判定には gap・列 padding・南海帯予約・ticker 高さを px 単位で含め、`data-left/right/center-natural-height-px` / `-capacity-px` 等の診断属性で外部から照合可能にする。
- **ソルバの解決順**（時計の中央維持が最優先の目的関数）:
  1. 左右 2 列に全カードが収まる割当を全列挙で探す（左先頭は津波→地震固定）。
  2. 不成立なら中央資格カードを中央受け皿へ移して時計退避（stage 2）。中央も実測容量で判定。
  3. それでも不成立なら余白・行間圧縮（stage 3）。**フォントサイズは縮めない**。
- viewport resize 時は再測定・再配置する（モックは初回のみだったが本実装は追従する）。

## 5. 劣化のはしご

| stage | 状態 | 条件 |
|---|---|---|
| 0 | 通常（時計中央・左右 2 列） | 左右に全カードが収まる |
| 1 | 左退避 | 右列超過分の非資格カードが左列の実測空きへ |
| 2 | 時計退避 | 左右で不成立。時計は ticker 右下（緊急画面と同位置）へ、中央資格カードを中央へ |
| 3 | 余白圧縮 | 中央込みでも不成立。余白・行間のみ圧縮（文字サイズ死守） |

- 判定は決定的（同一入力→同一 stage）。バタつきは実測閾値に余裕を持たせて抑える。
- モック実測の基準値: 1920×1080 で列容量 807px、全 7 domain コンパクト合計 ≈1660px → max 相当は stage 2 が数値上の正解（左右のみ不成立）。

## 6. 地域リスト適応展開と気象警報カード改修

- **A→B の一方向**: ソルバ（A）が配置と枠を確定した後、余裕がある列のカードだけが展開（B）する。展開がソルバの再実行を誘発しない。
- 展開対象: 地震カードの震度地域行（「ほか n 地域」→実地域名）・気象警報の対象地域。展開候補は engine 側 snapshot の復元候補（最大 24 地域、グリッド期資産 grid-region-expansion）を流用する。
- **WeatherAlertCard 本改修**（モックでは mock 側 CSS で試作済み・本実装でコンポーネントへ移す）:
  - 対象地域リストの 2 列組版（県名と地域の組は pref-group 単位で保ち、列間で泣き別れさせない）。
  - 竜巻注意情報・竜巻目撃情報の対象地域フル表示（現行の「ほか」省略を廃止）。

## 7. 変化アニメーション

- カードの自然高さが更新報で変化した場合、高さ・位置の変化をトランジションで繋ぐ（瞬間ジャンプさせない）。
- 実装はグリッド期の motion planner / epoch coordinator の決定的確定パターン（Animation.finished 一次＋deadline backstop）を流用候補とする。詳細は実装時に scoped spec で詰める。
- stage 遷移（時計退避・復帰）にも同じ方針を適用する。

## 8. マーキーの扱い

- 実表示では現行どおり走行マーキー（津波バナー・熱中症カード）。
- モック・静止画評価では in-flow 静止化する（走行 transform は overflow clip で閉じ込められないことが実測で判明済み。静止画での本文可読性も担保される）。
- 本実装の目視 packet 撮影時も静止化パラメータを用意する。

## 9. 受け入れ条件

### 9.1 機械検証可能（テスト・ゲートが判定）

- `npm run build` / `npm test` / `npm --prefix display run build|test|typecheck` 全緑。
- 実ブラウザ実測ゲート: scenario（4/7/max 相当 fixture）× viewport（1920×1080・1512×982・実機 720p）で、診断属性が「切れゼロ・重なりゼロ・全カード配置済み or 意図した stage」を示す。
- ソルバ決定性: 同一入力・入力順 shuffle で同一配置。
- 時計位置: stage 0/1 で viewport 中央から 0px、秒表示が全対象 viewport で非欠損。
- unknown 抑止数と受信ログの一致。
- 既知の悪い配置（わざと容量超過にした fixture）でゲートが FAIL すること（ゲート自体の反証テスト）。

### 9.2 人間検証必須（ご主人の目視 packet が判定）

| 項目 | 主張 | 基線 | 反証条件 |
|---|---|---|---|
| 平時の姿 | 時計中心の秩序が基線より整う | 現行 main・モック v13 | 「基線の方が落ち着く」裁定 |
| 多発時の姿 | stage 2/3 でも読み取りが破綻しない | モック v13 max | 「どこを見ればいいか分からない」裁定 |
| 距離可読性 | 実機の視聴距離で主情報が読める | 現行実機 | 実機 gate で読めない項目の指摘 |
| 変化の体感 | 更新時の動きが追える（§7） | 現行（瞬間切替） | 「変化に気づけない/うるさい」裁定 |

- **Oracle と証跡**: 目視 packet（§10）のスクリーンショット集とご主人の GO/NO-GO 記録。
- **判定者と時点**: ご主人。変更単位ごと（実装後）＋ main 合流前（最終）＋ Pi 実機反映後（実機 gate）。

## 10. 目視 packet ゲート運用

- 実装の変更単位ごとに、「代表シナリオ＋最悪ケース数枚＋基線との並列比較＋問い（最大 3 つ）」を数分で裁定できる packet として提出する。
- **目視 GO のない main 合流を禁止**する。無応答は GO と数えない。
- 微修正・非視覚変更・裁定済みの狭い変更はリスク分類により目視を省略できる（省略した事実を記録する）。
- 「比較の結果、変更しない」は正規の成功として扱う。

## 11. 実装対象の見取り図

- `display/frontend/src/components/StandbyScreen.svelte` — 3 列等幅化・時計絶対中央・実測 2 パス＋ソルバ・はしご・縦中央揃え（最大の変更単位）。
- `WeatherAlertCard.svelte` — 2 列組版・竜巻フル表示（§6）。
- engine 側 — unknown 抑止（表示排除＋ログ record）・地域展開候補の供給（グリッド期資産の移植）。
- モックの実測棚・ソルバ・診断属性のロジックは本実装への移植元とする（モックは spec の実証プロトタイプとして残す）。
- 変更単位の分割・委譲契約・レビュー階梯（実装→Sol high→xhigh→**目視 GO**→合流）は plan 側で確定する。
