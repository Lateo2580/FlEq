# CLI 端末の表示設計

新築（reconstruction）の `fleq` が端末に出すものの見た目と文面を決める。
R10①（2026-09-19 作者）の「CLI 表示設計 spec」で、C19 `P3-TERMINAL-OUTPUT-001` の契約はこの spec を材料に起草する。
作り方（出力が詰まっても受信を止めない作り、受信の結果を受け取る口、REPL の結線）は契約に書き、ここには書かない。

状態: 起草を終えた（2026-11-01〜03、作者と一緒に起草した。10 月 31 日の作者裁定）。2026-11-04 に、実端末の目視と 3 本の批評を受けて、図の往復で §2〜§5 の見た目を改めた（P3-TERMINAL-LAYOUT-001）。

## 1. 端末の役目

新築では、Pi の Chrome の画面が主な表示になる。
端末は、それに次ぐ第 2 のメイン画面で、作者が SSH で覗く面と、画面を使わずに CLI だけで使う利用者の面である（2026-11-04 作者）。

電文の中身をどこまで出すかは、分野で分ける（2026-11-01 作者裁定、案 C）。

| 出し方 | 分野（新築の unit） |
|---|---|
| 表まで出す | 緊急地震速報（eew）、地震（seismic: 震度速報、震源、震源・震度、顕著な地震の震源要素更新、長周期地震動の観測）、津波（tsunami） |
| 短い形 | 気象警報（weather-current）、気象の時系列（weather-timeseries）、土砂災害（landslide）、洪水（flood）、竜巻と記録的短時間大雨など（local-bulletins）、台風（typhoon）、気象解説（briefing）、火山（volcano）、南海トラフ（nankai） |

短い形の分野の本文は、端末に出さず Pi の画面で読む（例外は台風の暴風域に入る確率の府県の行。§5.4、Q-TO16-VPTA50）。南海トラフの情報と火山の解説（VFVO51・VFVO60・VZVO40）の本文は、本文を返す API（`P3-BULLETIN-TEXT-API-001`）で Pi の画面のプログラムへ届き、それを描く画面は P4 で作る。噴火警報の防災事項（VFVO50）は alerts の view で届く（`P3-RESTORE-DROPPED-TEXT-001`）。噴火警報の活動の文は unit の state に持たないので、view でもこの API でも読めない。

## 2. 全体の約束

- どの幅でも、行が端末の右端を越えて折り返し、表の列がずれることをしない（2026-08-26 監査の A3）。
- 要点（震度、階級、特殊値）を切り詰めで消さない（監査 A2 と中程度の 1 件）。地域名も詰めない（§4）。
- 利用者の目に触れる文字列で、開発の中の言い換え（「窓」「枠」など）を使わない。利用者が知っている呼び名と、時刻、件数、地域名で書く（2026-10-30 作者）。
- 端末への出力が詰まっても、電文の受信を止めない（spec:382。作り方は契約）。
- 合格の基準は「鳴って顔を上げた瞬間に、重さ・場所・行動が読める」とする（2026-11-04 作者裁定、Q-TO2-ROOT）。作者と同居人は別の作業をしていて、通知が鳴ったときや横目で端末を見る。上から順に読むことを当てにせず、文字と配置で意味が通ることを先に満たす。線と色はその上に載せる。
- 途中から見ても読めるようにする。前の行を覚えていることを当てにしない（津波の区分を各行に出す、§5.3）。

## 3. 重さごとの見た目

最大震度 5 弱以上か長周期地震動階級 2 以上で、端末の警報の見た目にする（H08）。
帯の段は、重い順に「最も重い」「紫」「警報」「注意」「地の色なし」の 5 つと、取消のピンク系（§5 の各分野の表、Q-TO-EEW-8・Q-TO-Q-2・Q-TO-T-3・Q-TO3-LEVEL）。
帯は、警報以上と取消を、幅いっぱいに地の色で塗る。注意は字と罫線の色で表し、地を塗らない。「塗られていたら警報以上」と形で読めるようにする（Q-TO2-STYLE）。
最も重い段の帯は白の地に黒の太字にして、画面で最も明るい帯にする。紫の意味は、縦線と字で運ぶ（Q-TO3-TOP）。
旧築の二重罫線の枠（`src/ui/formatter.ts` の critical）は使わない（Q-TO-EEW-1）。1 通のまとまりは、左の縦線と電文の前の空行で表す（§5.0）。

### 3.2 色の付け方

- 色は chalk 4.1.2（root の package.json に今ある依存）で付ける（Q-TO-COLOR-2）。chalk 6 は ESM 専用・Node 22 以上で、新築と旧築の CommonJS の build と Node 20 の約束に合わず、NO_COLOR も読まない（2026-11-03 に source で確かめた）。
- 足すのは 2 つ。環境変数 NO_COLOR が空でなければ色を付けない。chalk が 16 色か 256 色と判定した端末は、フルカラーに引き上げる（旧築の `src/index.ts` と同じ。Windows PowerShell などで判定が外れるため）。
- 色が無くても、帯の文字（電文の題名）と震度・階級の値は文字で読める。色だけで区別する部分を作らない。
- 色を付けないとき（NO_COLOR、パイプ、ファイル）は、帯を塗らず ━ の形で出し、左の縦線とその字下げも出さない（Q-TO2-NOCOLOR）。塗りの空白だけでは帯に見えないため。
- 標準出力が端末でない（パイプ、ファイルへのリダイレクト）ときは、chalk の判定どおり色を付けない。

## 4. 幅

幅は出力のたびに端末の桁数（process.stdout.columns）を読み、途中で窓の大きさを変えても次の出力から合わせる。全角の字は 2 桁で数える。
線と本文の右端は端末の幅に合わせ、100 桁で止める。右端を 1 つにするため、本文も同じ上限で折る（Q-TO2-W）。
帯と表は、端末の幅で一律に形を切り替えない。入るかどうかを、その帯・その表ごとに実際の幅で決める（Q-TO2-W。一律に 2 行へ割ると、15 桁で済む「5強  静岡県中部」まで 4 行に割れた）。
縦線だけは 60 桁未満で外す。縦線は 2 桁使い、56 桁の端末で津波の表を 1 地域 1 行に保てなくなるため（fixture の津波 27 本のうち 7 本）。

どの幅でも、次のとおりにする（§2 の約束を幅に当てたもの）。

- 帯: 題名と発表時刻が 1 行に入れば 1 行で出す。入らなければ、塗る帯は「発表」を落とし、それでも入らなければ時刻を次の行に出す。
- 表の列（津波の区分・地域・予想される高さ・到達予想時刻、緊急地震速報の予測震度・地域・到達予想時刻・長周期階級）は、次の順で入る形を探す。(1) 図のとおりの列幅 (2) 見出しを短くして値に合わせた列幅（「予想」「到達」「長周期」。高さの列は「予想」を落とさない、Q-TO3-MEANING） (3) 列の間を 1 桁にする (4) 1 地域を地域の行と値の行の 2 行に分ける。
- 表の中身を切り詰めない。地域名、区分、震度、階級、高さ、時刻、到達の文を省略しない。
- 全部の行が空の列は出さない。
- FlEq が項目を並べて組む行（震源の行）は、入らなければ「 ・ 」の境で折る。折り目の「 ・ 」は出さず、続きの行を 2 字下げる。語の途中で折らない。1 項目が幅を超えるときだけ字の境目で折る（Q-TO3-WRAP）。
- 電文の文（見出し文、地震情報や短い形の本文の引用）は、1 行に入ればそのまま出す。入らなければ句点で分け、それでも入らない文は字の境目で折って 2 字下げる。字の境目で折った行の行頭に、句読点、閉じ括弧、感嘆符と疑問符、小書きの仮名、長音を置かない（Q-TO7-KINSOKU）。図の中で幅を超える行（§5.4 の本文など）も、図の形は 1 行で描いてあるだけで、出すときは折り返す。URL は途中で折らずに 1 行で出す。
- 地域の一覧（震度や階級の段の後ろに全角の空白で並べる地域、津波予報の地域、津波の観測点）は、幅で折り返し、2 行目からは地域の列の位置まで字下げする。震度と長周期階級の一覧は、折り返した行にも段の字を出す（§5.2 の図。途中から見ても読めるように、Q-TO3-WRAP）。津波予報の地域は、60 桁未満では字下げを 12 桁でなく 2 桁にする（一覧の行数を抑えるため）。
- §3.1 の差は、「黒と」の値は黒い地、「Nightfox の地と」の値は作者の地で測った。黒い地の値は、暗い青の地では 2〜3 割下がる。白い地の端末では、黄の罫線などが読みにくくなる（旧築も同じ前提）。

- 端末の桁数が取れない（パイプ、ファイル）ときは 80 桁として扱う。
- 旧築の `tablewidth` の設定は引き継がない（spec §11.3、2026-09-14 作者「廃止可」）。

## 5. 分野ごとの形

### 5.0 電文のブロックの組み立て（共通）

（§8 の Q-TO2-*）

1 通の電文は、上から次の順に組む。

1. 空行 1 行（Q-TO2-GAP。行間を変えられない端末で、電文の境目を読めるようにする）
2. 帯（題名と発表時刻）
3. 要点（何が・どこで・何をすべきか）
4. 区切りの罫線と地域の表
5. 区切りの罫線と補足（見出し文、定型の文）
6. 末尾の再掲（長い報だけ）
7. 末尾の行（電文の種類のコードと ID）。容量の上限で記録に入らなかった地震・津波の続報だけ、その後に記録に入っていない旨の 1 行を足す（下の末尾の行の項）

- 帯の下の行は、すべて左に縦線を通す（§3.1）。図の `▌` は縦線を表す。実際には地の色の空白 1 桁で、その後に空白 1 桁を置く。60 桁未満と色を付けないときは出さない。
- 地の色で塗る帯は、図では前後の空白で表す。実際には幅いっぱいに塗る。
- 要点の最大震度の行は太字にする（旧築の最大予測震度の行と同じ）。
- 要点に並べる地域は、最大の段の地域だけにする。入らない分は「ほか n 地域」と書く。全部の地域は表に出す。長周期地震動の観測情報（VXSE62）は階級の行のままで、地域を添えない。
- 区切りの罫線は薄い字で、帯の右端まで引く。要点・表・補足のまとまりの間に 1 本引き、表の直後は次が末尾の行でも 1 本引く。末尾の再掲は補足のまとまりに入れる。表も補足も無い報は引かない。
- 図の帯と区切りの線の長さは省略して描いてある。電文の文も図では 80 桁の幅で折っていない。線の長さと折り方は §4 に従う。
- 末尾の行は薄い字で `VXSE43 ・ ID 20240417231454` の形にする（Q-TO-EEW-2。時刻に見えないように名前を付ける）。容量の上限で unit が中身を記録せず印だけを付けた地震・津波の続報（U-Q の VXSE51・52・53・61・62 と U-T の VTSE41。その入力の outcome の subject の transition が unavailable、P3-CC-AC03 (2)）は、今のとおり報を出し、末尾の行の後（報のブロックの最後）に「容量の上限のため、この報は記録に入っていません」を黄 #f0e442 の字で 1 行出す。この 1 行のある報だけ末尾の行は最後の行でなくなり、並びは 末尾の再掲（出るとき）→ 末尾の行 → この 1 行（再掲は今のとおり末尾の行の上）。この 1 行は末尾の再掲の 20 行に数えない。新しい地震・新しい subject を断った報は今のとおり出さない。U-W・U-F の容量の印の報には付けない（P3-TERMINAL-CAPACITY-NOTE-001、P3-TCN-D-PLACE=B、2026-11-12 の作者の裁定）。
- 末尾の再掲: 帯から末尾の行までの実際に出る行（折り返しの後の行。空行は数えない）が 20 行以上のとき、緊急地震速報・地震・津波で、要点を発表時刻つきで末尾の行の上にもう一度出す（Q-TO2-RECAP。旧築の「▼ サマリー」に当たる）。再掲には場所と行動を残す。津波は最も重い区分の地域名の行と行動の文、緊急地震速報は最大の行と行動の文を出す（Q-TO3-RECAP）。流れ終わったときに、画面に残る場所へ危険を残すため。その報の再掲に限り、今も有効かは言わない。再掲の行に「旧の値 →」は写さない。長周期地震動の観測情報は「最大長周期階級 3 ・ 最大震度 5弱」の行を再掲する。訓練と試験の報は、時刻の括弧に印を足す（「（14:49:00 発表・訓練）」。帯が流れた後に実の報に見えないように）。

つも無い報は帯と末尾の行だけのまま（「ありません」とは書かない）、取消の報には出さない。火山や気象のほかの報はまとまりを止めず、待たずに出るので、まとまりはその下に出る。取り直しの報は今のとおり端末に出ない。まとめた報は届いた時に定期要約に数える。

## 6. 電文以外の出力

### 6.1 接続の状態

- 切れている間は「切断中、再接続を試行中／最終受信 HH:MM」を目立たせ、繋がり直したら消す（H24）。切れた 3 行（帯の題名と罫線・本文・下の罫線）はクリーム #ffff99、戻った 3 行は明るい緑 #87e7b0（2026-11-03 作者裁定）。
- 1 回の切断に 1 回デスクトップ通知を出す。何度も切れたら「回線が不安定です」の 1 つにまとめる（H24、H25、spec 16.2.4）。
- 一度も繋がらないときは、理由（ネット、API キー）と対処の手引きを出す（H29）。

（§8 の Q-TO-C-1〜4）

端末は流れていく出力なので、出した行を後から消せない。
そこで「目立たせて、繋がり直したら消す」は REPL の入力の行（旧築の `FlEq [● 21:05:40]>`）で行い、切れたときと戻ったときにだけ 1 回ずつ行を出す。

21:03:12 に最後に受信し、21:03:40 に切断に気付いた場面（切れたときに出す行）

```
━ 回線が切れました ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 21:03:40 ━
21:03:12 から受信できていません。自動で繋ぎ直しています。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

切れている間の入力の行

```
FlEq [21:03:12 から 切断中・繋ぎ直し 3 回目]>
```

ミュート中の入力の行（Q-TO2-MUTE。起動時の 1 行だけでは、鳴らない設定が過去の行へ流れるため）。切断中は 56 桁に入るように、繋ぎ直しの回数と期限と条件を外す。条件つきのミュートは「ミュート中（条件つき）」、期限もあれば「ミュート中（条件つき） 21:30 まで」と書く。

```
FlEq [○ 00:00:05 ミュート中]>
FlEq [○ 00:00:05 ミュート中 21:30 まで]>
FlEq [21:03:12 から 切断中・ミュート中]>
```

21:06:02 に繋がり直した場面（戻ったときに出す行。入力の行は元に戻る）

```
━ 回線が戻りました ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
21:03:12 から 21:06:02 まで（2 分 50 秒）受信できていませんでした
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 「最終受信」の時刻は、dmdata の生存確認（ping）を含めた最後の受信の時刻とする（Q-TO-C-2）。HostStatus.lastFrameWallMs がこの時刻（P3-DC2-AC04）。電文だけの時刻にすると、静かな日は何時間も前の時刻になり、切れ始めの時刻にならない。
- デスクトップ通知の文は「回線が切れました（21:03:12 から受信できていません）」。音は付けない。`notify` で切れるようにする（Q-TO-C-3）。
- 30 分の間に 3 回切れたら、3 回目の通知を「回線が不安定です（30 分で 3 回切れました）」にし、その後 30 分続けて繋がるまで、切れるたびの通知を出さない（Q-TO-C-3）。端末の行は切れるたびに出す。

一度も繋がらないときに出す行（Q-TO-C-4）。理由は HostStatus.lastFailure から選ぶ。

| lastFailure | 端末に出す文 |
|---|---|
| network | dmdata.jp に繋がりません。ネットワークの接続を確かめてください。繋がるまで自動で試し続けます。 |
| authRejected | API キーが dmdata.jp に受け付けられませんでした。`fleq init` か `fleq config set apiKey <key>` で設定し直してください。 |
| capacity | この API キーで開ける接続の数が上限に達しています。ほかのパソコンなどで動いている FlEq を止めるか、dmdata.jp の契約の接続数を確かめてください。 |
| dmdata | dmdata.jp が接続を受け付けませんでした。しばらくしてから自動で繋ぎ直します。 |
| startUncertain | 接続を始められたか確かめられませんでした。自動で繋ぎ直します。 |
| noContract | dmdata.jp に有効な契約がありません。dmdata.jp で区分を契約すると、自動で繋ぎ直して受信を始めます。（受信の後も、noContract になったときに 1 回出す） |

### 6.2 定期要約（互換必須）

（§8 の Q-TO-R-1・Q-TO-R-2）

旧築の形（`src/ui/summary-interval-formatter.ts`）

```
── 10分要約 ── EEW 1件 | 地震 3件 | 津波 1件 (最大5弱)
受信 ▁▁▂▁▁▁▃▁▁█▁▁▁▁▂▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁  (30分)
```

新築の形（21:30 に出す 10 分ごとの要約の場面）

```
── 21:20〜21:30 の受信 ── EEW 1件 ・ 地震 3件（最大震度 5弱） ・ 津波 1件 ・ 気象 12件
```

- 「10分要約」を、何時から何時までかの時刻に置き換える（利用者の目に触れる所で「要約の間隔」などの言い換えを使わない）。
- 分野の名前は EEW、地震、津波、南海トラフ、火山、気象の 6 つ。気象は、気象警報、気象の時系列、土砂災害、洪水、竜巻と記録的短時間大雨など、台風、気象解説をまとめて数える。旧築の要約は気象を数えていなかった。容量の上限で記録に入らなかった地震・津波の続報（§5.0 の末尾の行の項）も、端末に出した報として件数と最大震度に数える（P3-TCN-D-SUMMARY=A）。
- 受信の無い分野は出さない。どの分野も 0 件なら「受信なし」と出す（旧築と同じ）。
- 1 行だけにする。1 分ごとの受信の数の棒（sparkline）は出さない（Q-TO-R-1、2026-11-01 作者）。spec §11.4 の「定期要約・sparkline」の行は 2026-09-14 に互換必須としたが、sparkline の部分はこの裁定で廃止に改める（spec 本文の行の改訂は C19 の契約の起草で当てる）。
- 間隔は `--summary-interval` と REPL の `summary` で変える（C18 の発注 3）。

### 6.3 当日地震履歴（互換必須）

端末には出さない。
旧築の当日地震履歴は、Pi の画面の待機中の表示（今日の地震の件数と直近の地震）の材料で、画面を切っていても更新し続けるという機能だった（`src/engine/monitor/display-sink.ts` の dailyQuakes）。旧築も端末には出していない。
新築では地震の unit の SeismicDailyHistory が、画面とは関係なく受信ごとに更新して保存する（P3-UNIT-Q-001、配送済み）。取り消された地震の印と件数の扱いは H18 のとおりで、P3-UNIT-Q-CAPACITY-001 の P3-QC-AC07 が持つ。
互換必須の中身は配送済みの unit で満たしているので、C19 で作るものは無い。

### 6.4 待機中の tips（互換必須）

```
  Tip: notify eew on のように分野ごとに通知を変えられます。
```
- 待機中の tips の前に空行を 1 行置く（電文のブロックの末尾の行にすぐ続けて出すと、tips が電文の続きに読める。Mac mini の写しの 2026-11-08〜09 で 13 か所）。幅（100 桁まで）に入らない tips は、電文の文と同じく句点で分け、それでも入らない文は幅の中の最後の読点「、」の後で折って 2 字下げる（読点で折るのは tips だけで、電文の文の折り方は §4 のまま）。幅の中に読点が無い文は字の境目で折って 2 字下げるが、半角の英数字の並び（「35℃」「M9.0」「earthquake」など）の途中では折らず、並びの手前で折る（並びが続きの行に入らないときだけ字の境目。P3-TL15-D-TIP-DIGITS、P3-TERMINAL-LAYOUT-015）。次の項の「1 行」は幅に入る tips の形。2026-11-09 作者、P3-TERMINAL-LAYOUT-013。
- 旧築と同じく、補足の薄い字で、先頭を 2 字下げて、幅に入る tips は 1 行出す。既定の間隔は 30 分（旧築の waitTipIntervalMin と同じ）。間隔は REPL の `tipinterval` で変える（C18 の発注 3）。
- 中身は旧築の `src/tips/` の知識の tips（地震学、津波、気象、緊急地震速報、歴史など）をそのまま使う。
- コマンドの tips（commands-basic、commands-advanced）は、新築の REPL にあるコマンドの分だけ残し、廃止したコマンド（`history`、`mode`、`tablewidth`、`infotext` など）の分は除く（spec §11.5「廃止可: UI、help、設定 key、文書、関連コードを一緒に除く」）。

### 6.5 起動時の update check（互換必須）

```
新しい版があります: v4.1.0 → v4.2.0  npm install -g @sayue_ltr/fleq@latest
```

- 確かめ方は旧築と同じ（npm、失敗したら GitHub、24 時間の cache、`FLEQ_NO_UPDATE_CHECK` で止める）。
- 旧築の英語の文「Update available」を日本語にする（Q-TO-R-2）。コマンドの部分は補足の薄い字。package の名前は package.json の name を使う。

### 6.6 起動時のまとめ

起動して、止まっていた間に出た情報を取り直し終えたら（C16 の起動時のダイジェスト、spec 16.2.3）、端末にも 1 つのブロックで出す（Q-TO-D-1）。中身は C16 のダイジェストの形をそのまま写す（分野ごとに新しい順で見出し 3 件まで、残りは種類ごとの件数。P3-REC-D-DIGEST-BUDGET）。電文の本文は取らないので、最大震度などは出さない。

```
━ 止まっていた間に出た情報（7 日前まで） ━━━━━━━━━━━━━━━━━━━━━
津波       取り直せませんでした
地震         5 件
  06:12  震源・震度に関する情報
  04:40  震度速報
  02:31  震度速報
  ほか 震源に関する情報 2 件
火山       304 件
  07:00  降灰予報（定時）
  06:10  噴火に関する火山観測報
  04:00  降灰予報（定時）
  ほか 降灰予報（定時） 300 件　噴火に関する火山観測報 1 件
```

- 新しい 3 件より後の分は、種類の題名と件数で「ほか 降灰予報（定時） 300 件」と書く。同じ題名の種類（指定河川洪水予報の VXKO50〜89 など）は件数を足し、2 つ以上なら件数の多い順に全角の空白で並べる。題名の表は Q-TO8-NO-CODE のとおりで、表に無い種類は「その他」にまとめる（Q-TO-D-2 を改めた）。見出しの行は時刻と題名だけで、見出し文は出さない。題名が取り直しの 256 バイトの上限で切られたときは、末尾の印を … にする。分野の名前は太字。件数は右に揃える。0 件の分野は出さない（Q-TO8-DIGEST）。
- 「ほか」の行が幅に入らないときは、題名の途中では折らず「題名 n 件」の組の境で折り、続きの行は 1 つ目の題名の位置（「  ほか 」の後の 7 桁）まで下げる（Q-TO16-DIGEST-WRAP。2026-11-10 の作者の裁定 A。気象警報・注意報時系列情報の種類の行と同じ折り方）。1 つの組だけで幅を越えるときだけ、その組を字の境目で折り、続きの行も 7 桁下げる。例: 2026-11-09 23:05 の Mac mini の写し（100 桁）の「ほか 降灰予報（定時） 289 件　火山の状況に関する解説情報 11 件　推定噴煙流向報 3 件　噴火に関する／火山観測報 3 件」は、「推定噴煙流向報 3 件」の後で折れ、次の行が「       噴火に関する火山観測報 3 件　噴火警報・予報 1 件」になる。
- 取り直せなかった分野は「取り直せませんでした」と書き、0 件と書かない（C16 の unsatisfied）。
- 7 日より前に止まっていたときは、見出しの罫線の下に「7 日より前の情報は取り直していません」の 1 行を薄い字で出す（P3-REC-D-DIGEST-WINDOW）。
- ダイジェストが作られないとき（電文の区分を購読していない、起動時に取り直さない）は、何も出さない。全部の分野が 0 件のとき（取り直せなかった分野が無く、7 日より前の印だけがあるときも）も、帯ごと何も出さない（Q-TO8-DIGEST）。
- 時刻は電文の発表時刻（reportDateTime）。無ければ dmdata の受信時刻。
- 旧築は起動時にこのまとめを出さなかった。画面での見せ方は P4 で決める。

### 6.7 起動画面（互換必須）

（§8 の Q-TO8-BANNER）

2026-11-08 07:00 に、緊急地震速報だけを契約している API キーで、既定の区分のまま起動した場面（appName は fleq-next、版は 4.1.0）。

- 帯の行は旧築と同じく、空行の後に空色 #56b4e9 の地に黒の太字で出し、後ろに空行を 1 行置く。1 行が端末の幅（線の右端と同じ、桁数と 100 の小さい方）に入らないときは、「<appName> v<版>」を帯の色で 1 行目に、2 桁下げた「Project DM-D.S.S リアルタイム地震・津波情報モニター」を 2 行目に出す（副題の字も帯の色、字下げの 2 桁は塗らない。P3-TL20-D-BANNER-SECOND=B、2026-11-11 の作者の裁定。「 — 」は出さない。2 行目も入らなければ字の境目で折る。P3-TL20-D-BANNER-WRAP、2026-11-11 の作者の依頼）。appName は dmdata の接続名（設定の appName）、版は root の package.json の version（P3-CLI-D-VERSION と同じ 1 つ）。帯は host を起こす前に出す（旧築も契約の確かめの前に出した）。

- 未契約の行は、求めた区分のうち start の区分に無いものを、求めた順に 1 行ずつ黄 #f0e442 の字で出す。旧築は契約の一覧の API で確かめて「スキップします」と書いたが、新築は start の区分と比べる（dmdata が受け付けた区分だけが届く）。起動時は契約の一覧で契約の無い区分を外して start に送り、外した区分もこの行で出す（P3-DMDATA-NO-CONTRACT-001）

- 旧築の起動の行のうち、求めた区分の行（`受信区分:`）、音の再生の確かめの行、ナイトモードなど新築に無い設定の行は出さない。

## 7. 緊急地震速報のログファイル（互換必須）

書式は旧築に合わせる（`src/engine/eew/eew-logger.ts` の buildReportBlock）。

現況の字は、今の入力の行の字（時計、回線、ミュート）の後ろ、閉じ括弧の前に置く。

- 載せる情報が無いときの入力の行は、§6.1 の字のまま変えない。

### 9.3 並びと回り方

- いちばん重い段の項目だけを出す。軽い段の項目は出さず、回さない。顔を上げた瞬間に軽い字が見えないようにするため。
- 段の中の並びは、津波、南海トラフ、火山、気象、洪水、土砂の順にする。同じ分野の中は subject の昇順、1 つの subject の中は電文の順にする。U-N は南海トラフの系統を VYSE60 の系統より先に置く。
- 字がまったく同じ項目は 1 つにまとめる（別の官署の同じ区分など）。
- 項目が 2 件以上なら、5 秒ごとに次の項目へ回し、`1/3` の形で何番目かを付ける。1 件なら番号を付けない。
- 回す位置は、その時の時計の値から計算する（壁時計の 5 秒の区切りの数を枠の数で割った余り）。枠は項目 1 件に 1 つで、§9.4 の切断とミュートの枠があればそれも数える。タイマーと「今どれか」の覚えを足さない。枠の数が変わった直後は位置が飛んでよい。
- 字の再計算は今のまま 1 秒ごとにする。画面の再描画は今の条件（command が走っていず、入力中の文字が空で、書き出しが終わったとき）のときだけ行う。

### 9.4 入らない幅

現況を足した字の幅が端末の桁数に収まらないときは、次の形にする。
「収まる」は、全部の項目の §9.1 の形の字の幅が、端末の桁数より小さいことをいう。全角の字は 2 桁で数える。

```
FlEq [切断中 大津波警報 岩手県 1/3]>
FlEq [切断中 大津波警報 宮城県 2/3]>
FlEq [切断中 大津波警報 福島県 3/3]>
FlEq [切断中 21:03:12 から・ミュート中]>
```

- 切れている間は `切断中` の字をどの瞬間も残す。切断の時刻と、ミュート中か繋ぎ直しの回数の字は、最後の 1 つの枠として項目と一緒に回す（Q-TO6-NARROW）。
- 繋がっている間のミュートは、今の字の形（`FlEq [○ 21:40:05 ミュート中 21:30 まで]>`）を最後の 1 つの枠として回す。項目の枠にはミュートの字を出さない。
- `1/3` は項目の数え方のままで、切断とミュートの枠は数えず、その枠に番号を付けない。項目が 1 件で枠が 2 つのときは番号を付けない。
- 枠を足すのは切断中と、繋がっている間のミュート中だけ。繋がっていてミュートでないときは足す枠が無い。
- 繋がっている間の項目の枠が時計つきで収まらないときは、全部の項目の枠で時計を外す（Q-TO6-CLOCK）。回線の印は残す。ミュートの枠の字は変えない。

```
FlEq [● 南海トラフ地震臨時情報（巨大地震警戒）]>
```

- 切れている間の項目の枠に時計は無く、`切断中` の字を外さない。それでも入らなければ行は折り返す。繋がっている間も、時計を外してなお入らなければ行は折り返す。
- 残存: 入力の行が折り返すと、報の前に消すのは 1 行だけなので、報のたびに 1 行目の字が画面に残る。56 桁で切断中、南海トラフの字を含む 2 件のとき（`FlEq [切断中 南海トラフ地震臨時情報（巨大地震警戒） 1/2]> ` は 58 桁）に起きる形。
- 項目の字は切り詰めない（§2）。

### 9.5 消えるとき

- 解除、取消、期限切れで unit の view から外れたら、次の字の再計算（1 秒ごと）で字から消える。画面の再描画は §9.3 の条件のときで、入力中の文字があるときは、Enter の後の入力の行か、次の電文の後の入力の行で消える。
- 今も有効かの期限は各 unit が持つ。洪水は 36 時間、土砂は 48 時間、南海トラフは 7 日（巨大地震警戒から移った現況は 14 日）で view から外れる。津波の予報、火山の警報、気象に時間の期限は無く、解除の報か取消の報まで残る。
- 起動の直後は、復元した view の値を最初の入力の行から出す。気象は復元して未確認の行が view に入らないので、確かめる報が来てから出る。
- 手元の時計を確かめる前（起動から最長 30 秒、P3-CK-AC01）は、止まっている間に期限が来た値を unit が view に残す。入力の行もその値を出す。Pi の画面と同じ値を見るため。確かめられないまま 30 秒が過ぎると unit が view から外す。
- 残存: 切断中に解除され、再接続の取り直しが失敗すると、次の報まで字が残る。U-T に時間の期限が無い。U-V・U-W も同じ。安全側の誤りで、印は足さない（Q-TO6-RECOVERY）。
- 取り直しで受けた報は本文を端末に出さない（§6.6）が、view が変わるので入力の行の字は変わる。
- 切れている間も最新の view に従う。受信では変わらないが、1 秒の tick は回線によらず期限を当てるので、期限では変わる。期限の無い値は切断の前のまま `切断中` の字と一緒に出し続ける。

## 10. Windows の書き出し

（契約は P3-TERMINAL-WINDOWS-001。判断カード「Windows の端末の出力」の案 B、2026-11-07 作者裁定。ここの Q-TW-* は §9 までの行を動かさないために §8 の表に足さず、この節に書く）

12:00 に PowerShell（従来の conhost）の字を選択したまま席を立つと、端末への書き込みは 12:10 に選択を解くまで返らない。
この間に届く電文の受信を止めない（例外は下の残存の標準エラーの行）。
`quit` と Ctrl+C の終わりでも固まらない（例外は同じ行）。

- Windows では書き込み専用の子プロセスを 1 本立て、子が標準出力へ直に書く。親は子の出力を受けて転送しない。親が書くと `WriteConsoleW` で親が止まるため（Q-TW-WRITER）。
- 標準出力が端末でも pipe でも file でも子へ回す。Windows の pipe の書き込みは同期で、今の worker の書き方だと読み手が止まったときに終われない（Q-TW-NONTTY）。
- 字の中身、列の上限、古い単位を落とす規則、省いた件数の行は macOS と Linux と同じ。12:10 に選択を解くと列に残った報が出て、落とした分は「（表示が間に合わなかったため、N 件の表示を省きました）」の 1 行になる。
- 子が起動できない、途中で落ちた、親との通信が切れたときは、受信を止めず、以後この端末には出さない。標準エラーに「端末へ書き出す子プロセスが止まったため、この端末には電文や返事を出しません」を書きにいくのは 1 回だけで、書けなかったときは知らせのないまま以後の出力が捨てられる（起動の資源が足りない、標準エラーの行き先が切れている）。子は立て直さない（Q-TW-FAIL）。
- 終わるときは列の残りと緊急地震速報のログを最長 1 秒書かせ、子を終わらせて親は待たずに終わる。子が消える時刻は保証しない（Q-TW-CLOSE）。
- macOS と Linux の書き方は変えない。
- 残存: Windows Terminal などの ConPTY では、読み手が止まると親の console の操作（端末の大きさの取得、入力の mode の変更）まで待ちが及ぶ可能性がある。確信度は中で、実機で確かめる（Q-TW-DEVICE）。
- 残存: 親が標準エラーへ直に書く行が残り、上の受信と終わりの約束の例外になる（Q-TW-MAIN-CONSOLE）。受信の最中は診断の保存の失敗と溢れの行で、字の選択中に起きると選択を解くまで受信が止まる。停止の中と後は dmdata の socket の片付けの失敗の行と、設定の保存を確かめられない行と、REPL が閉じた後に分かった設定の保存の失敗の行（P3-REPL-CLOSED-001）で、字の選択中に起きると選択を解くまで 1 秒の終わりに届かない。標準エラーの pipe の読み手が消えていると、この書き込みの失敗で親が終わる。
- 実機で確かめること（Q-TW-DEVICE、P5 の切替の前）: conhost の字の選択の間の受信と 1 秒の終了、Windows Terminal の同じ操作、日本語の字と色、幅と大きさの変更、Ctrl+C と `quit`、子の起動の時間とメモリ。

## 11. 処理の停止（P3-OWNER-STOP-NOTICE-001）

（契約は P3-OWNER-STOP-NOTICE-001。2026-11-13 19 時台の作者の決め。§6 の中に入れないのは、行を足すと §6 より後の行を引く契約の «» がずれるため。§6.1 の文は変えない）

急ぐ側（urgent）の owner は、緊急地震速報・津波・南海トラフ・火山（U-E・U-T・U-N・U-V）を処理する。
この owner の thread が例外で落ちると、FlEq は作り直さずに止まる（P3-C3B-AUTO-RESTART=A）。
止まったことを、端末の帯・デスクトップ通知・音で 1 回知らせる。

21:12:00 に U-T の VTSE41 の処理で urgent の owner が落ちた場面（80 桁）

```
━ 緊急地震速報などの処理が止まりました ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
21:12:00 から、緊急地震速報・津波・南海トラフ・火山の情報を処理していません。
FlEq を起動し直してください。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 形は回線の帯（§6.1）と同じで、見出しの帯・本文・下の罫線。見出しに時刻を入れない。2 行目の時刻は止まった時刻で、診断の file の ERROR ownerStopped と同じ読み。
- 56 桁の端末では 2 行目が書き出しの折り返しで 2 行に折れ、そのままにする。帯のための折り返しは足さない。
- 色は 4 行とも、切れた回線の行と同じクリーム #ffff99（色の役目 connLost、P3-OSN-D-COLOR=A）。新しい色の役目は足さない（§3.1 の表は変えない）。
- デスクトップ通知を 1 回出す。題は「FlEq」、本文は「緊急地震速報などの処理が止まりました。FlEq を起動し直してください。」（P3-OSN-D-DESKTOP-TEXT=A）。
- 音を 1 回鳴らす。資材は気象の警報の音 `reconstruction/assets/sounds/weather-warning.wav`（P3-OSN-D-SOUND=A）。新しい音は作らない。
- 帯は設定によらずいつも出す。デスクトップ通知と音を止めるのは次の 2 つだけで、分野の on/off（`notify`）は見ない（P3-OSN-D-MUTE=A）。
  - ミュートが効いている間で、ミュートの条件に緊急地震速報（分野 eew）の条件が 1 つも無いとき（条件の無いミュートを含む）は、デスクトップ通知も音も出さない。緊急地震速報を条件にしたミュートの間は、両方を出す。
  - sound off の間は音だけ出さない。
- ミュートは止まった時の時計で 1 回だけ判じる。後でミュートを解いても出し直さない。
- デスクトップ通知と音は、通知の門と A7 の channel を通らない（回線の切断のデスクトップ通知と同じ道）。鳴っている別の通知の音と重なりうる。成否は記録せず、backend の無い環境では黙って何も出ない。
- 同じ run で出すのは 1 回だけ。起動し直すまで、緊急地震速報・津波・南海トラフ・火山の電文は画面にも音にも出ない（作り直しは P5）。
- 停止を求めた後（`quit`、Ctrl+C）に止まったときは出さない（P3-OSN-D-SHUTDOWN=A）。終了の段と code は変えない。
- 出ないとき: seismic・weatherCurrent・deferred の owner が止まったとき。urgent の owner が応答しない（thread は生きている）とき。どちらも今のまま、Chrome の状態の行と診断の file だけに出る。
