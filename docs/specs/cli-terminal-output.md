# CLI 端末の表示設計

新築（reconstruction）の `fleq` が端末に出すものの見た目と文面を決める。
R10①（2026-09-19 作者）の「CLI 表示設計 spec」で、C19 `P3-TERMINAL-OUTPUT-001` の契約はこの spec を材料に起草する。
作り方（出力が詰まっても受信を止めない作り、受信の結果を受け取る口、REPL の結線）は契約に書き、ここには書かない。

状態: 起草を終えた（2026-11-01〜03、作者と一緒に起草した。10 月 31 日の作者裁定）。2026-11-04 に、実端末の目視と 3 本の批評を受けて、図の往復で §2〜§5 の見た目を改めた（P3-TERMINAL-LAYOUT-001）。

## 1. 端末の役目

新築では、Pi の Chrome の画面が主な表示になる。
端末は、それに次ぐ第 2 のメイン画面で、作者が SSH で覗く面と、画面を使わずに CLI だけで使う利用者の面である（2026-11-04 作者）。

電文の中身をどこまで出すかは、分野で分ける（2026-11-01 作者裁定、案 C）。

| 出し方 | 分野（新築の unit） |
|---|---|
| 表まで出す | 緊急地震速報（eew）、地震（seismic: 震度速報、震源、震源・震度、顕著な地震の震源要素更新、長周期地震動の観測）、津波（tsunami） |
| 短い形 | 気象警報（weather-current）、気象の時系列（weather-timeseries）、土砂災害（landslide）、洪水（flood）、竜巻と記録的短時間大雨など（local-bulletins）、台風（typhoon）、気象解説（briefing）、火山（volcano）、南海トラフ（nankai） |

短い形の分野の本文（南海トラフの臨時情報、噴火警報の文など）は、Pi の画面で読む。

## 2. 全体の約束

- どの幅でも、行が端末の右端を越えて折り返し、表の列がずれることをしない（2026-08-26 監査の A3）。
- 要点（震度、階級、特殊値）を切り詰めで消さない（監査 A2 と中程度の 1 件）。地域名も詰めない（§4）。
- 利用者の目に触れる文字列で、開発の中の言い換え（「窓」「枠」など）を使わない。利用者が知っている呼び名と、時刻、件数、地域名で書く（2026-10-30 作者）。
- 端末への出力が詰まっても、電文の受信を止めない（spec:382。作り方は契約）。
- 合格の基準は「鳴って顔を上げた瞬間に、重さ・場所・行動が読める」とする（2026-11-04 作者裁定、Q-TO2-ROOT）。作者と同居人は別の作業をしていて、通知が鳴ったときや横目で端末を見る。上から順に読むことを当てにせず、文字と配置で意味が通ることを先に満たす。線と色はその上に載せる。
- 途中から見ても読めるようにする。前の行を覚えていることを当てにしない（津波の区分を各行に出す、§5.3）。

## 3. 重さごとの見た目

最大震度 5 弱以上か長周期地震動階級 2 以上で、端末の警報の見た目にする（H08）。
帯の段は、重い順に「最も重い」「紫」「警報」「注意」「地の色なし」の 5 つと、取消のピンク系（§5 の各分野の表、Q-TO-EEW-8・Q-TO-Q-2・Q-TO-T-3・Q-TO3-LEVEL）。
帯は、警報以上と取消を、幅いっぱいに地の色で塗る。注意は字と罫線の色で表し、地を塗らない。「塗られていたら警報以上」と形で読めるようにする（Q-TO2-STYLE）。
最も重い段の帯は白の地に黒の太字にして、画面で最も明るい帯にする。紫の意味は、縦線と字で運ぶ（Q-TO3-TOP）。
旧築の二重罫線の枠（`src/ui/formatter.ts` の critical）は使わない（Q-TO-EEW-1）。1 通のまとまりは、左の縦線と電文の前の空行で表す（§5.0）。

### 3.2 色の付け方

- 色は chalk 4.1.2（root の package.json に今ある依存）で付ける（Q-TO-COLOR-2）。chalk 6 は ESM 専用・Node 22 以上で、新築と旧築の CommonJS の build と Node 20 の約束に合わず、NO_COLOR も読まない（2026-11-03 に source で確かめた）。
- 足すのは 2 つ。環境変数 NO_COLOR が空でなければ色を付けない。chalk が 16 色か 256 色と判定した端末は、フルカラーに引き上げる（旧築の `src/index.ts` と同じ。Windows PowerShell などで判定が外れるため）。
- 色が無くても、帯の文字（電文の題名）と震度・階級の値は文字で読める。色だけで区別する部分を作らない。
- 色を付けないとき（NO_COLOR、パイプ、ファイル）は、帯を塗らず ━ の形で出し、左の縦線とその字下げも出さない（Q-TO2-NOCOLOR）。塗りの空白だけでは帯に見えないため。
- 標準出力が端末でない（パイプ、ファイルへのリダイレクト）ときは、chalk の判定どおり色を付けない。

## 4. 幅

幅は出力のたびに端末の桁数（process.stdout.columns）を読み、途中で窓の大きさを変えても次の出力から合わせる。全角の字は 2 桁で数える。
線と本文の右端は端末の幅に合わせ、100 桁で止める。右端を 1 つにするため、本文も同じ上限で折る（Q-TO2-W）。
帯と表は、端末の幅で一律に形を切り替えない。入るかどうかを、その帯・その表ごとに実際の幅で決める（Q-TO2-W。一律に 2 行へ割ると、15 桁で済む「5強  静岡県中部」まで 4 行に割れた）。
縦線だけは 60 桁未満で外す。縦線は 2 桁使い、56 桁の端末で津波の表を 1 地域 1 行に保てなくなるため（fixture の津波 27 本のうち 7 本）。

どの幅でも、次のとおりにする（§2 の約束を幅に当てたもの）。

- 帯: 題名と発表時刻が 1 行に入れば 1 行で出す。入らなければ、塗る帯は「発表」を落とし、それでも入らなければ時刻を次の行に出す。
- 表の列（津波の区分・地域・予想される高さ・到達予想時刻、緊急地震速報の予測震度・地域・到達予想時刻・長周期階級）は、次の順で入る形を探す。(1) 図のとおりの列幅 (2) 見出しを短くして値に合わせた列幅（「予想」「到達」「長周期」。高さの列は「予想」を落とさない、Q-TO3-MEANING） (3) 列の間を 1 桁にする (4) 1 地域を地域の行と値の行の 2 行に分ける。
- 表の中身を切り詰めない。地域名、区分、震度、階級、高さ、時刻、到達の文を省略しない。
- 全部の行が空の列は出さない。
- FlEq が項目を並べて組む行（震源の行）は、入らなければ「 ・ 」の境で折る。折り目の「 ・ 」は出さず、続きの行を 2 字下げる。語の途中で折らない。1 項目が幅を超えるときだけ字の境目で折る（Q-TO3-WRAP）。
- 電文の文（見出し文、地震情報や短い形の本文の引用）は、1 行に入ればそのまま出す。入らなければ句点で分け、それでも入らない文は字の境目で折って 2 字下げる。行頭に句読点を置かない。図の中で幅を超える行（§5.4 の本文など）も、図の形は 1 行で描いてあるだけで、出すときは折り返す。URL は途中で折らずに 1 行で出す。
- 地域の一覧（震度や階級の段の後ろに全角の空白で並べる地域、津波予報の地域、津波の観測点）は、幅で折り返し、2 行目からは地域の列の位置まで字下げする。震度と長周期階級の一覧は、折り返した行にも段の字を出す（§5.2 の図。途中から見ても読めるように、Q-TO3-WRAP）。津波予報の地域は、60 桁未満では字下げを 12 桁でなく 2 桁にする（一覧の行数を抑えるため）。
- §3.1 の差は、「黒と」の値は黒い地、「Nightfox の地と」の値は作者の地で測った。黒い地の値は、暗い青の地では 2〜3 割下がる。白い地の端末では、黄の罫線などが読みにくくなる（旧築も同じ前提）。

- 端末の桁数が取れない（パイプ、ファイル）ときは 80 桁として扱う。
- 旧築の `tablewidth` の設定は引き継がない（spec §11.3、2026-09-14 作者「廃止可」）。

## 5. 分野ごとの形

### 5.0 電文のブロックの組み立て（共通）

（§8 の Q-TO2-*）

1 通の電文は、上から次の順に組む。

1. 空行 1 行（Q-TO2-GAP。行間を変えられない端末で、電文の境目を読めるようにする）
2. 帯（題名と発表時刻）
3. 要点（何が・どこで・何をすべきか）
4. 区切りの罫線と地域の表
5. 区切りの罫線と補足（見出し文、定型の文）
6. 末尾の再掲（長い報だけ）
7. 末尾の行（電文の種類のコードと ID）

- 帯の下の行は、すべて左に縦線を通す（§3.1）。図の `▌` は縦線を表す。実際には地の色の空白 1 桁で、その後に空白 1 桁を置く。60 桁未満と色を付けないときは出さない。
- 地の色で塗る帯は、図では前後の空白で表す。実際には幅いっぱいに塗る。
- 要点の最大震度の行は太字にする（旧築の最大予測震度の行と同じ）。
- 要点に並べる地域は、最大の段の地域だけにする。入らない分は「ほか n 地域」と書く。全部の地域は表に出す。長周期地震動の観測情報（VXSE62）は階級の行のままで、地域を添えない。
- 区切りの罫線は薄い字で、帯の右端まで引く。要点・表・補足のまとまりの間に 1 本引き、表の直後は次が末尾の行でも 1 本引く。末尾の再掲は補足のまとまりに入れる。表も補足も無い報は引かない。
- 図の帯と区切りの線の長さは省略して描いてある。電文の文も図では 80 桁の幅で折っていない。線の長さと折り方は §4 に従う。
- 末尾の行は薄い字で `VXSE43 ・ ID 20240417231454` の形にする（Q-TO-EEW-2。時刻に見えないように名前を付ける）。
- 末尾の再掲: 帯から末尾の行までの実際に出る行（折り返しの後の行。空行は数えない）が 20 行以上のとき、緊急地震速報・地震・津波で、要点を発表時刻つきで末尾の行の上にもう一度出す（Q-TO2-RECAP。旧築の「▼ サマリー」に当たる）。再掲には場所と行動を残す。津波は最も重い区分の地域名の行と行動の文、緊急地震速報は最大の行と行動の文を出す（Q-TO3-RECAP）。流れ終わったときに、画面に残る場所へ危険を残すため。その報の再掲に限り、今も有効かは言わない。再掲の行に「旧の値 →」は写さない。長周期地震動の観測情報は「最大長周期階級 3 ・ 最大震度 5弱」の行を再掲する。訓練と試験の報は、時刻の括弧に印を足す（「（14:49:00 発表・訓練）」。帯が流れた後に実の報に見えないように）。

### 5.1 緊急地震速報

| 部分 | 色の役目 |
|---|---|
| 帯 | 警報の色の地に黒の太字（予報は注意の色の字と罫線） |
| 発表時刻 | 塗る帯は帯の字のまま、塗らない帯は補足の薄い字 |
| 前の報の値と矢印（「4 →」「5.8 →」）、表の見出し、区切りの罫線、末尾の行 | 補足の薄い字 |
| 最大予測震度の行 | 強調の太字、値は震度の色の段 |
| 見出し文の地方名（四国、九州、中国） | 強調の太字 |
| 予測震度の値（6弱、5強、5弱） | 震度ごとの色の段 |
| 長周期階級の値 | 長周期の階級ごとの色の段 |
| 到達と推測、発表より前の到達予想時刻 | 警報の字 |
| 行動の文 | 強調の太字 |

- 最大予測震度の行は、見出し文の有無によらず常に要点の先頭に置く（Q-TO2-LAYOUT。旧の Q-TO-EEW-7 の入れ替えをやめた）。
- 見出し文の「豊後水道で地震」は、震源の行と重なるので出さない（文の先頭が震源名と「で地震」のときだけ外す。「四国　九州　中国で強い揺れ」は残す）。
- 電文の到達の条件は確かさを変えずに出す。「既に主要動到達と推測」は「到達と推測」と書く。「到達済み」とは書かない（Q-TO3-MEANING）。
- 発表時刻より前の到達予想時刻は、到達と推測と同じ警報の字で出す。
- 警報の報の行動の文（電文の Comments の WarningComment、「強い揺れに警戒してください。」）は、言い換えずに要点に太字で出す（Q-TO3-ACTION）。文の無い予報の報には足さない。
- 続報の値は、値の場所に「旧の値 →  新の値」で出す。矢印の後ろの空白は 2 つにする（Q-TO3-ARROW。作者の字体で → が 2 桁分に描かれ、空白 1 つでは次の字に食い込むため）。旧の値と矢印は補足の薄い字にする（Q-TO2-FOLLOW）。最大予測震度、震源の名前、M、深さ、長周期階級で同じ形にする。地域の増減の件数は出さない（作者）。長周期階級は、旧か新が 0 か無いときは矢印を付けない（0 の項目は出さないため）。
- 比べる相手は、同じ運用区分・同じ電文の種類（VXSE43 と VXSE45 は別）・同じ EventID の前の報にする。2 つの種類は別の番号で並走するので、種類をまたいで比べると番号も順も合わない。
- 仮定の震源の報（PLUM）の M と深さは画面に出ない仮の値なので、比べる値にしない。
- 変わらなかった値には何も付けない。「同じです」のような比較の文は出さない（作者）。
- 前の報の覚えが無い報（起動の直後、EventID の覚えから落ちた報）では、矢印を出さない。
- 地域が 1 つで、到達も長周期階級も無い報は、表が要点の行の繰り返しになるので表を出さない。
- 同じ EventID で VXSE45 を受けた後の VXSE43 の報は出さない。取消は種類によらず最初の 1 通だけ出す（Q-TO3-EEW-FOLD。旧築 `eew-tracker.ts` の hasSeen45 の決まり。VXSE44 は新築の端末に届かない）。
- 別の地震の緊急地震速報が進んでいる間は、取消を除く報の要点の最後に「ほかに 1 件の緊急地震速報（石川県能登地方）」と出す。震源名が無ければ括弧を付けない。2 件以上は「ほかに 2 件の緊急地震速報」と書く（Q-TO3-EEW-OTHERS。旧築の「ほかにN件の速報あり」）。最終報と取消を受けた地震と、最後の報を受け取ってから 10 分を過ぎた地震は数えない（旧築と同じ期限。時計は端末の現在時刻で、電文の時刻で測らない）。
- 旧築から外すもの: 精度、緯度経度、検知時刻、発生時刻、震源の「海域」（Q-TO-EEW-2）。緯度経度はログファイルに残る（§7）。精度は旧築のログファイルにも無い。
- 地域の一覧は、電文に載る地域を全部出す（Q-TO-EEW-3）。電文は予測震度 3 以上の地域だけを載せる（fixture の VXSE43・VXSE45 で確かめた）。
- 震源名は、M の行の先頭に「震源: 」を付けて常に出す（Q-TO-EEW-4）。
- 「予想」と「予測」は「予測」に揃える（統合担当、旧築の「最大予測震度」に合わせた）。地域名は電文の字のまま出す。
- 設定した地域が電文の一覧に載らない（震度 3 未満の見込みの）ときは、何も出さない（Q-TO-EEW-5、spec 16.3 の未定の答え）。設定した地域が一覧に載るときの出し方（印を付けるか、先頭に寄せるか）は未定で、市区町村と緊急地震速報の地域の対応表（H50、別の契約）に頼る。

### 5.2 地震

- 「最終受信」の時刻は、dmdata の生存確認（ping）を含めた最後の受信の時刻とする（Q-TO-C-2）。HostStatus.lastFrameWallMs がこの時刻（P3-DC2-AC04）。電文だけの時刻にすると、静かな日は何時間も前の時刻になり、切れ始めの時刻にならない。
- デスクトップ通知の文は「回線が切れました（21:03:12 から受信できていません）」。音は付けない。`notify` で切れるようにする（Q-TO-C-3）。
- 30 分の間に 3 回切れたら、3 回目の通知を「回線が不安定です（30 分で 3 回切れました）」にし、その後 30 分続けて繋がるまで、切れるたびの通知を出さない（Q-TO-C-3）。端末の行は切れるたびに出す。

一度も繋がらないときに出す行（Q-TO-C-4）。理由は HostStatus.lastFailure から選ぶ。

| lastFailure | 端末に出す文 |
|---|---|
| network | dmdata.jp に繋がりません。ネットワークの接続を確かめてください。繋がるまで自動で試し続けます。 |
| authRejected | API キーが dmdata.jp に受け付けられませんでした。`fleq init` か `fleq config set apiKey <key>` で設定し直してください。 |
| capacity | この API キーで開ける接続の数が上限に達しています。ほかのパソコンなどで動いている FlEq を止めるか、dmdata.jp の契約の接続数を確かめてください。 |
| dmdata | dmdata.jp が接続を受け付けませんでした。しばらくしてから自動で繋ぎ直します。 |
| startUncertain | 接続を始められたか確かめられませんでした。自動で繋ぎ直します。 |

### 6.2 定期要約（互換必須）

（§8 の Q-TO-R-1・Q-TO-R-2）

旧築の形（`src/ui/summary-interval-formatter.ts`）

```
── 10分要約 ── EEW 1件 | 地震 3件 | 津波 1件 (最大5弱)
受信 ▁▁▂▁▁▁▃▁▁█▁▁▁▁▂▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁  (30分)
```

新築の形（21:30 に出す 10 分ごとの要約の場面）

```
── 21:20〜21:30 の受信 ── EEW 1件 ・ 地震 3件（最大震度 5弱） ・ 津波 1件 ・ 気象 12件
```

- 「10分要約」を、何時から何時までかの時刻に置き換える（利用者の目に触れる所で「要約の間隔」などの言い換えを使わない）。
- 分野の名前は EEW、地震、津波、南海トラフ、火山、気象の 6 つ。気象は、気象警報、気象の時系列、土砂災害、洪水、竜巻と記録的短時間大雨など、台風、気象解説をまとめて数える。旧築の要約は気象を数えていなかった。
- 受信の無い分野は出さない。どの分野も 0 件なら「受信なし」と出す（旧築と同じ）。
- 1 行だけにする。1 分ごとの受信の数の棒（sparkline）は出さない（Q-TO-R-1、2026-11-01 作者）。spec §11.4 の「定期要約・sparkline」の行は 2026-09-14 に互換必須としたが、sparkline の部分はこの裁定で廃止に改める（spec 本文の行の改訂は C19 の契約の起草で当てる）。
- 間隔は `--summary-interval` と REPL の `summary` で変える（C18 の発注 3）。

### 6.3 当日地震履歴（互換必須）

端末には出さない。
旧築の当日地震履歴は、Pi の画面の待機中の表示（今日の地震の件数と直近の地震）の材料で、画面を切っていても更新し続けるという機能だった（`src/engine/monitor/display-sink.ts` の dailyQuakes）。旧築も端末には出していない。
新築では地震の unit の SeismicDailyHistory が、画面とは関係なく受信ごとに更新して保存する（P3-UNIT-Q-001、配送済み）。取り消された地震の印と件数の扱いは H18 のとおりで、P3-UNIT-Q-CAPACITY-001 の P3-QC-AC07 が持つ。
互換必須の中身は配送済みの unit で満たしているので、C19 で作るものは無い。

### 6.4 待機中の tips（互換必須）

```
  Tip: notify eew on のように分野ごとに通知を変えられます。
```

- 旧築と同じく、補足の薄い字で、先頭を 2 字下げて 1 行出す。既定の間隔は 30 分（旧築の waitTipIntervalMin と同じ）。間隔は REPL の `tipinterval` で変える（C18 の発注 3）。
- 中身は旧築の `src/tips/` の知識の tips（地震学、津波、気象、緊急地震速報、歴史など）をそのまま使う。
- コマンドの tips（commands-basic、commands-advanced）は、新築の REPL にあるコマンドの分だけ残し、廃止したコマンド（`history`、`mode`、`tablewidth`、`infotext` など）の分は除く（spec §11.5「廃止可: UI、help、設定 key、文書、関連コードを一緒に除く」）。

### 6.5 起動時の update check（互換必須）

```
新しい版があります: v4.1.0 → v4.2.0  npm install -g @sayue_ltr/fleq@latest
```

- 確かめ方は旧築と同じ（npm、失敗したら GitHub、24 時間の cache、`FLEQ_NO_UPDATE_CHECK` で止める）。
- 旧築の英語の文「Update available」を日本語にする（Q-TO-R-2）。コマンドの部分は補足の薄い字。package の名前は package.json の name を使う。

### 6.6 起動時のまとめ

起動して、止まっていた間に出た情報を取り直し終えたら（C16 の起動時のダイジェスト、spec 16.2.3）、端末にも 1 つのブロックで出す（Q-TO-D-1）。中身は C16 のダイジェストの形をそのまま写す（分野ごとに新しい順で見出し 3 件まで、残りは種類ごとの件数。P3-REC-D-DIGEST-BUDGET）。電文の本文は取らないので、最大震度などは出さない。

```
━ 止まっていた間に出た情報（7 日前まで） ━━━━━━━━━━━━━━━━━━━━━
津波       取り直せませんでした
地震       5 件
  06:12  震源・震度に関する情報  （見出し文）
  04:40  震度速報               （見出し文）
  02:31  震度速報               （見出し文）
  ほか VXSE52 2 件
気象警報   2 件
  05:10  気象警報・注意報        （見出し文）
  ほか VPWW54 1 件
```

- 新しい 3 件より後の分は、電文の種類のコードと件数で「ほか VXSE52 2 件」と書く。種類が 2 つ以上なら全角の空白で並べる（「ほか VXSE52 2 件　VXSE51 1 件」）。C16 のダイジェストは残りの件数を種類のコードでしか持たず、題名を引く表を足さない（Q-TO-D-2）。
- 取り直せなかった分野は「取り直せませんでした」と書き、0 件と書かない（C16 の unsatisfied）。
- 7 日より前に止まっていたときは、見出しの罫線の下に「7 日より前の情報は取り直していません」の 1 行を薄い字で出す（P3-REC-D-DIGEST-WINDOW）。
- ダイジェストが作られないとき（電文の区分を購読していない、起動時に取り直さない）は、何も出さない。
- 時刻は電文の発表時刻（reportDateTime）。無ければ dmdata の受信時刻。
- 旧築は起動時にこのまとめを出さなかった。画面での見せ方は P4 で決める。

## 7. 緊急地震速報のログファイル（互換必須）

書式は旧築に合わせる（`src/engine/eew/eew-logger.ts` の buildReportBlock）。
材料は U-E が受信の outcome の facts.report に載せる（P3-EEW-FACTS-001、配送済み）。
取消の報には、取消の文だけを書き、震源も仮定震源の印も書かない（§5.1、Q-TO-L-1）。取消の電文は Earthquake の要素を持たない（2024-06-13 の VXSE43 の取消で確かめた）ので、旧築も新築の facts.report の isAssumedHypocenter も false になる。
仮定の震源の報の M と深さは仮の値なので、前の報として比べない。仮定の報の次の確定の報の変化の行に、M と深さの変化を書かない（Q-TO5-LOG）。
